2 File-system essentials

Proficiencies

File system concepts:

  • Spatial metaphor of “location” in a hierarchical tree of folders and files.
  • The current working directory.
  • Specifying a location using a “path” string.
  • Specifying absolute vs. relative paths.
  • Program or executable pathss.

Every file you will use in this course — a Julia script, a downloaded dataset, a saved figure — lives somewhere on a computer’s file system. Before writing a line of Julia, it helps to have a precise vocabulary for where things are and how to say so in text. This chapter builds that vocabulary. The next chapter, on the shell, puts it to work.

2.1 Files and directories

Term Meaning
File A named unit of stored data: a Julia script, a CSV table, an image, a PDF.
Directory (folder) A container that groups files and other directories.
Path A text string that names the location of a file or directory.
Root The single directory that contains, directly or indirectly, everything else.

“Directory” and “folder” name the same thing. “Directory” is the older, more technical term, used by the shell and by Julia; “folder” is the term most graphical file managers show on screen. This text uses both, and treats them as synonyms.

A file system organizes files by nesting directories inside other directories, to any depth. A directory can hold files, other directories, or both. This nesting is what makes it possible to have a clean_data.jl file in a scripts directory and a completely different clean_data.jl file in a data directory, without either overwriting the other: the 2 files have the same name but different locations.

2.2 The directory tree

Because directories can nest inside directories, the whole arrangement forms a tree. One directory, the root, sits at the top; everything else hangs beneath it, directly or through a chain of intermediate directories.

project/
├── data/
│   ├── raw/
│   │   └── observations.csv
│   └── processed/
│       └── observations_clean.csv
├── scripts/
│   ├── clean_data.jl
│   └── analyze.jl
├── figures/
│   └── summary_plot.png
└── Project.toml

Reading this diagram: project is a directory containing 2 other directories (data, scripts) and 1 file (Project.toml). data in turn contains 2 directories, raw and processed, each holding 1 file. Indentation and the tree lines show nesting; they are not part of any name.

A few relational terms are useful:

Term Meaning In the example above
Parent directory The directory that directly contains a given file or directory. data is the parent of raw.
Subdirectory / child A directory directly contained by another. raw and processed are subdirectories of data.
Ancestor Any directory reached by repeatedly following parents upward. project is an ancestor of observations.csv.

“Climbing” the tree means moving toward the root, from a file or directory to its parent, grandparent, and so on. “Descending” means moving from a directory into one of its subdirectories.

NoteThe tree has more than 1 root

The diagram above shows a project’s root — the top-level directory of one particular collection of files. The whole file system also has its own single root, discussed later in this chapter under standard file-system organization. A project’s top directory is not the same thing as the file system’s root, even though both are informally called “the root” of whatever tree is under discussion.

2.3 Paths: writing a location as text

A path is a string that specifies the location of a file or directory by naming the sequence of directories that lead to it.

data/raw/observations.csv

This path names 3 things in sequence, separated by a path separator: the directory data, the directory raw inside it, and the file observations.csv inside that. The separator is a forward slash, /, on macOS and Linux, and traditionally a backslash, \, on Windows, although modern Windows tools, including Julia, generally also accept forward slashes.

Component Example Role
Separator / (macOS, Linux) or \ (Windows) Marks the boundary between 1 directory name and the next.
Directory name data, raw 1 segment of the path.
File name observations.csv The final segment, naming the file itself.
Extension .csv The suffix of the file name, usually indicating file type.
TipJulia hides the separator problem for you

Writing separators by hand is fragile: a path built with / breaks on a system that expects \, and vice versa. Once Julia is in the picture, joinpath builds paths using whatever separator the current operating system expects, so code that constructs paths does not need to hard-code either character. This is covered when program files are introduced.

2.4 Absolute paths and relative paths

A path can be written in 2 ways: starting from the file system’s root, or starting from wherever the reader currently is.

Kind Starts from Example
Absolute path The file-system root /home/student/project/data/raw/observations.csv
Relative path The current location data/raw/observations.csv

An absolute path always identifies the same file or directory, no matter where it is written or read from — it fully specifies the route from the root. A relative path is only meaningful together with a starting point. The same relative path, data/raw/observations.csv, refers to different files depending on where it is interpreted from: from inside project, it reaches project/data/raw/observations.csv; from inside some other directory that happens to also contain a data subdirectory, it reaches a completely different file.

Absolute paths on macOS and Linux begin with /, the root itself:

/home/student/project/data/raw/observations.csv

Absolute paths on Windows begin with a drive letter:

C:\Users\student\project\data\raw\observations.csv

Relative paths never begin with a separator (on macOS or Linux) or a drive letter (on Windows); they begin directly with a name.

Question Use
Will this path be read from a known, fixed location? Absolute path
Is this path being written relative to a project folder that might live anywhere? Relative path
Am I sharing this path with someone using a different computer? Relative path

Relative paths are usually preferred for scripts and shared projects, since an absolute path baked into a script only works on the one computer where it was written. Absolute paths are useful for referring, unambiguously, to a specific location regardless of context — for example, when telling someone else exactly where a file lives.

2.5 The current working directory

Every running program — a shell session, a Julia session, a script being executed — has, at any moment, a current working directory: the location in the tree that relative paths are interpreted against. This is the “starting point” referred to in the definition of a relative path above.

The current working directory is not a property of a file or a program’s code; it is a property of the running session. The same script, executed twice from 2 different working directories, can resolve the same relative path to 2 different files. This is a common source of “file not found” confusion for beginners, and it is worth internalizing early: when a relative path does not seem to work, the first question is always what is the current working directory right now?

The next chapter shows how to ask the shell this question directly, and later chapters show the equivalent inside Julia. For now, the concept to hold onto is that “current working directory” names a real, specific location, even though it is not written down anywhere in the path string itself — it is implicit context that has to be tracked.

2.6 Special path segments: ., .., and ~

A few short symbols have fixed meanings inside a path, on macOS, Linux, and Windows alike.

Symbol Meaning
. The current directory itself.
.. The parent of the current directory.
~ The current user’s home directory (macOS, Linux; not standard on Windows).

These symbols can be combined with ordinary path segments. From inside project/scripts, the file project/data/raw/observations.csv can be reached with:

../data/raw/observations.csv

.. steps up from scripts to project; data/raw/observations.csv then descends back down from there. Repeating ../.. steps up 2 levels, and so on.

~ is a convenient shorthand for “wherever my home directory is,” which differs from user to user and machine to machine:

~/project/data/raw/observations.csv

is equivalent to, for example,

/home/student/project/data/raw/observations.csv

on a machine where the home directory is /home/student.

2.7 Program and executable paths

A program that can be run — julia, python, a compiled application — is, itself, a file: an executable file, sitting at some specific path on the file system, exactly like a data file or a script. Typing a bare name such as julia at a shell prompt does not magically invoke “the Julia program” in the abstract; it asks the shell to locate a file named julia (or julia.exe on Windows) among a specific list of directories it is configured to search, and then run that file.

That list of directories is called the search path, stored in an environment variable conventionally named PATH. When installation instructions say “make sure julia is on your PATH,” they mean: the directory containing the julia executable file must be one of the directories the shell searches when it sees the bare name julia typed as a command.

A program can also be run by giving its full path directly, bypassing the search entirely:

/usr/local/bin/julia

or, on Windows,

C:\Users\student\AppData\Local\Programs\Julia-1.12.6\bin\julia.exe

Both forms run the same executable file. The bare name is shorter and is what people normally type; the full path is unambiguous and does not depend on how the search path happens to be configured. The next chapter shows a shell command that reports exactly which file a bare program name resolves to.

2.8 Standard file-system organization

Every mainstream operating system organizes its file system according to broadly similar conventions, even though the exact names differ.

Concept macOS / Linux Windows
File-system root / 1 root per drive, e.g. C:\
Home directory /home/username (Linux) or /Users/username (macOS) C:\Users\username
Home directory shorthand ~ %USERPROFILE% (less commonly typed by hand)
Desktop, Documents, Downloads Subdirectories of the home directory Subdirectories of the home directory
Installed applications /Applications (macOS); scattered under /usr, /opt (Linux) C:\Program Files

For this course, the directory that matters most is the home directory: it is where a user account’s files live by default, where downloaded installers land (typically inside a Downloads subdirectory), and where per-user configuration for tools such as Julia is stored.

TipHidden files and dotfiles

On macOS and Linux, any file or directory whose name begins with a period, such as .gitignore or .bashrc, is treated as hidden: it is not shown by default in graphical file managers or in a plain directory listing. Hidden files are not special or protected — they are ordinary files that conventionally stay out of the way of everyday browsing, usually because they hold configuration rather than content a user edits directly.

Once Julia is installed, it keeps its packages and per-user configuration in a hidden directory named .julia inside the home directory (~/.julia). This is covered again when packages and environments are introduced.

2.9 Common pitfalls

Symptom Likely cause
A path that works on one computer fails on another. An absolute path was used where a relative one was needed.
A file “disappears” after a script runs from a different folder. The current working directory was not what was assumed.
A path with a space in it fails when typed at a shell prompt. Unquoted spaces are treated as separating multiple arguments; the next chapter covers quoting.
A file that should be there is not shown in a listing. The file’s name begins with . and is being hidden by default.
A path that worked on Linux fails, case-related, on another Linux machine. macOS and Windows file systems are usually case-insensitive by default; Linux file systems are case-sensitive, so Data.csv and data.csv are 2 different files.

  • How to change the current working directory based on:

    • relative paths

  • How to specify the location of a directory or a file as an argument to a program using both relative paths and absolute paths.

The previous chapter described paths and locations as text; this chapter puts that vocabulary to work. A shell is a program that reads commands typed as text and executes them, one line at a time. It is the primary tool for moving around the directory tree, inspecting what is there, and rearranging it — and it is also how Julia itself gets started, as the next section of this text will show.

NoteShell, terminal, and command line

These 3 terms are often used interchangeably by beginners, and this text does the same where the distinction does not matter. Precisely: a terminal is the window or application that displays text input and output; a shell is the program running inside it that actually reads and executes commands (common shells include bash, zsh, and PowerShell); “the command line” informally refers to the whole activity of typing commands into a shell.

3.1 Opening a shell

Platform Program How to open it
macOS Terminal Open from Applications → Utilities, or search “Terminal” in Spotlight.
Linux Varies by desktop environment — GNOME Terminal, Konsole, xterm, or similar Search “Terminal” in the application menu, or use the usual keyboard shortcut for your desktop environment.
Windows Windows Terminal or PowerShell Search “Terminal” or “PowerShell” in the Start menu.
Any platform VS Code’s integrated terminal Menu: View → Terminal, or the backtick shortcut (Ctrl-` / Cmd-`).

Any of these gives access to a shell. This text’s examples work in a Unix-style shell — bash or zsh, the default on macOS and Linux, and also available on Windows through VS Code’s integrated terminal, Git Bash, or Windows Subsystem for Linux (WSL). A short table of PowerShell and Command Prompt equivalents for Windows users who are not using a Unix-style shell appears near the end of this chapter.

3.2 The shell prompt

Once a shell is open, it displays a prompt and waits for input. A typical prompt looks something like:

student@laptop:~/projects/20260813--screech-owl$

showing the user name, the machine name, the current working directory (~/projects/20260813--screech-owl, using the ~ shorthand from the previous chapter), and a trailing symbol, here $, that marks where typed text will appear. The exact appearance varies by shell, configuration, and operating system.

NotePrompt markers are not part of the command

Because the full prompt is long and varies by machine, this text abbreviates it to a single $ in examples. $ identifies where a line is typed; it is not typed itself.

$ pwd

means: type pwd, then press Enter. Do not type the $.

Type a command and press Enter; the shell runs it, prints any output, and shows a fresh prompt.

3.3 Identifying the current working directory: pwd

The previous chapter introduced the current working directory as a concept: the location that relative paths are resolved against. The shell command pwd (“print working directory”) reports it directly.

$ pwd
/home/student/projects/20260813--screech-owl

This is always an absolute path. Whenever a relative path does not seem to point where expected, running pwd first is the standard way to check the assumption behind it.

3.4 Listing directory contents: ls

ls (“list”) shows the contents of a directory. With no arguments, it lists the current working directory:

$ ls
data  src  figures  Project.toml

Two flags are worth knowing early:

Flag Effect
ls -l “Long” listing: 1 entry per line, with type, permissions, size, and modification date.
ls -a Include hidden entries — files and directories whose names begin with ., as described in the previous chapter.
ls -la Both combined. 
$ ls -l
drwxr-xr-x  4 student student  128 Aug 20 09:14 data
drwxr-xr-x  3 student student   96 Aug 20 09:14 src
drwxr-xr-x  2 student student   64 Aug 20 09:14 figures
-rw-r--r--  1 student student  312 Aug 20 09:15 Project.toml

3.4.1 Listing another directory: relative and absolute arguments

ls accepts a path as an argument, and lists that location instead of the current working directory — using exactly the relative and absolute paths from the previous chapter:

$ ls data
processed  raw

$ ls ./data
processed  raw

$ ls /home/student/projects/20260813--screech-owl/data
processed  raw

All 3 commands above list the same directory, from the same starting working directory: the first 2 use relative paths (data and the equivalent, more explicit ./data), the third uses an absolute path.

3.5 Changing the current working directory: cd

cd (“change directory”) updates the shell’s current working directory.

$ pwd
/home/student/projects/20260813--screech-owl

$ cd data
$ pwd
/home/student/projects/20260813--screech-owl/data

cd accepts the same relative and absolute paths, and the same special segments, as any other path.

Command Effect
cd data Descend into the data subdirectory of the current location.
cd .. Move up to the parent directory.
cd /home/student/projects/20260813--screech-owl Jump directly to an absolute path.
cd ~ or cd (no argument) Return to the home directory.
cd - Return to the previous working directory (bash and zsh). 
$ cd data/raw
$ pwd
/home/student/projects/20260813--screech-owl/data/raw

$ cd ../..
$ pwd
/home/student/projects/20260813--screech-owl

$ cd
$ pwd
/home/student

$ cd -
/home/student/projects/20260813--screech-owls

Following cd with pwd (or ls) to confirm the new location is a good habit to confirm your location is correct, avoiding the potential for much frustration (when some commands do not work) or horrific tragedy (when some commands do work, but on the wrong files)

3.6 Invoking a program with a path location as an argument

ls data above is 1 example of a more general pattern: many programs take a path as an argument, telling them where to look. The same relative-versus-absolute choice applies no matter which program is being run. We might have a

$ julia src/analyze.jl
$ julia /home/student/project/crc/analyze.jl

Both invoke the same file, using the same two forms of path already introduced.

3.7 Correlating shell paths with the graphical file manager

The graphical file manager (Finder, File Explorer, or similar) and the shell describe the same file system, but show locations differently: one as icons and a navigable window, the other as text. Being able to translate between them is useful when, for instance, a data file was downloaded through a browser and now needs to be reached from a script.

  • macOS Finder: enable View → Show Path Bar to see the full path of the current folder at the bottom of the window; clicking the folder’s name in the window’s title bar shows a dropdown of its location in the hierarchy.
  • Windows File Explorer: click once in the address bar to reveal the full path as editable text, or right-click the address bar for a “Copy address as text” option.
  • Linux file managers: most (Nautilus, Dolphin, and others) support typing Ctrl-L to reveal or edit the path directly, or a path-bar toggle similar to Finder’s.
TipDrag a folder into the terminal

Most terminal applications, including Terminal on macOS, GNOME Terminal on Linux, and Windows Terminal, insert a file or folder’s path as plain text if its icon is dragged from the file manager into the terminal window. This is a quick way to get an exact absolute path without typing it by hand.

3.8 Creating a new directory: mkdir

$ mkdir results

creates a new, empty directory named results inside the current working directory. Creating a nested directory whose parents do not yet exist requires the -p flag:

$ mkdir -p results/2026-08-25/figures

-p creates every missing directory along the path — here, results, then 2026-08-25 inside it, then figures inside that — in 1 step, and does not raise an error if some of them already exist. Without -p, mkdir refuses to create a directory whose parent does not yet exist.

3.9 Copying files and directories: cp

cp source destination copies a file:

$ cp observations.csv observations_backup.csv

The destination can also be a directory, in which case the file is copied into it, keeping its original name:

$ cp data/raw/observations.csv data/processed/

Copying a directory requires the -r (“recursive”) flag, so that its contents are copied along with it:

$ cp -r data data_backup

Without -r, cp refuses to copy a directory.

3.10 Moving and renaming: mv

Unix-style shells use a single command, mv, for both moving a file to a different location and renaming it in place. This is not 2 unrelated features that happen to share a name: a rename is a move, to a new name within the same directory.

$ mv draft.jl analysis.jl

moves draft.jl to analysis.jl in the same directory — a rename.

$ mv analysis.jl scripts/

moves analysis.jl into the scripts directory, keeping its name — a move.

$ mv data data_archive

renames the whole data directory to data_archive; unlike cp, mv does not need a -r flag to move a directory, since nothing inside it is being duplicated.

Importantcp and mv overwrite silently

If the destination of cp or mv already exists, it is overwritten without confirmation and without a way to recover the original through the shell. Running ls on the destination first, before copying or moving into it, is a cheap habit that avoids this. Deleting files is intentionally not covered in this chapter; it is a more consequential operation than the 4 covered here, and is better introduced together with the safeguards around it.

3.11 Finding a program’s executable path: which

The previous chapter described running a program by its bare name as really asking the shell to search a list of directories, PATH, for a matching executable file. which reports the result of that search directly:

$ which julia
/usr/local/bin/julia

If no matching file is found anywhere on PATH, which reports nothing found, which is the same failure that produces a “command not found” error when the name is actually run.

3.12 Windows equivalents

Readers using PowerShell or Command Prompt directly, rather than a Unix-style shell, can use the following equivalents for the commands introduced above.

Task bash / zsh PowerShell Command Prompt (cmd.exe)
Show working directory pwd pwd (alias for Get-Location) cd (no argument)
List contents ls ls (alias for Get-ChildItem) dir
Change directory cd cd cd
Create directory mkdir mkdir mkdir
Copy a file cp Copy-Item copy
Copy a directory cp -r Copy-Item -Recurse xcopy /E
Move or rename mv Move-Item / Rename-Item move / ren
Find an executable which Get-Command where

PowerShell aliases several Unix-style names (pwd, ls, cp, mv) to its own underlying commands, so the left and middle columns often work identically in practice; cmd.exe does not, and uses its own distinct set of names.

3.13 A recommended beginner workflow

  1. Open a shell.
  2. Run pwd to confirm the starting location.
  3. Run ls to see what is already there.
  4. Use cd to reach the intended project directory.
  5. Use mkdir to create any missing directories before writing files into them.
  6. After any cp or mv, run ls again to confirm the result matches what was intended.

3.14 Common error messages

Symptom Likely cause First check
command not found The program name is misspelled, or its directory is not on PATH. which the-command-name
No such file or directory The path is wrong, or relative to an unexpected working directory. pwd, then ls on the intended parent directory.
Permission denied The current user does not have the needed access rights. Confirm the location and whether elevated permissions are genuinely required.
Is a directory cp was used on a directory without -r. Add -r.
mkdir: cannot create directory ... No such file or directory An intermediate directory in the path does not exist yet. Add -p.
mkdir: cannot create directory ... File exists A directory with that name is already there. ls to confirm; mkdir -p tolerates this case.
