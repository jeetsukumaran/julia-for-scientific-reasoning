Relaxed-clock phylogenetic inference with BEAST

Author

Jeet Sukumaran

BEAST 2 estimates posterior distributions of rooted, time-scaled phylogenetic trees and evolutionary-model parameters with Markov chain Monte Carlo (MCMC). This tutorial estimates the evolutionary timescale of 20 passerine birds from two mitochondrial sequence partitions. It uses an uncorrelated lognormal relaxed clock and an explicit calibration prior on the age of crown Passeriformes.

The workflow follows the Taming the BEAST beginner tutorial Molecular clock dating and modelling rate variation. The complete analysis uses BEAST’s graphical applications. It begins with two provided NEXUS alignments and creates every other file named below.

1 Preparation

1.1 Installing BEAST and its companion applications

Download the current BEAST 2 release for the operating system from the BEAST 2 website. The installation includes:

Application Role
BEAUti Defines the evolutionary model and writes the BEAST XML analysis file.
BEAST Samples trees and parameters from the posterior distribution.
LogCombiner Combines samples from independent BEAST runs.
TreeAnnotator Constructs and annotates a summary tree from sampled trees.

Install Tracer separately for examining parameter traces and effective sample sizes. Install FigTree for viewing the annotated tree.

Start BEAUti and select File | Manage Packages. Install the following BEAST packages:

Package Use in this analysis
bModelTest Averages the likelihood over nucleotide substitution models.
CCD Supplies the CCD0 posterior-tree summary used by TreeAnnotator.

Close and restart BEAUti after installing the packages. BEAUti loads newly installed templates when it starts. Record the installed BEAST, bModelTest, CCD, Tracer, and FigTree versions.

1.2 Acquiring the example alignments

Download both course alignments:

  • Download passerines_pc1.nex
  • Download passerines_pc2.nex

Create the following project directories with the file manager:

/home/student/projects/learning/scientific-julia/passerine-beast/
├── data/
│   ├── passerines_pc1.nex
│   └── passerines_pc2.nex
└── results/

Save the downloaded files as:

/home/student/projects/learning/scientific-julia/passerine-beast/data/passerines_pc1.nex
/home/student/projects/learning/scientific-julia/passerine-beast/data/passerines_pc2.nex

Both files contain the same 20 passerine species. passerines_pc1.nex contains the first codon positions and passerines_pc2.nex contains the second codon positions from the 13 mitochondrial protein-coding genes. Each alignment contains 3,616 nucleotide sites, for 7,232 sites in total. Third codon positions are excluded because their rapid evolution has produced substantial substitution saturation at this phylogenetic depth.

The first component of every sequence label identifies one of the three passerine suborders represented in the data:

ACANTHISITTI_Acanthisitta_chloris
TYRANNI_Pitta_nympha
PASSERI_Turdus_migratorius

The remaining labels follow the same SUBORDER_Genus_species form. These prefixes will be used to define taxon sets in BEAUti.

2 Basic workflow

2.1 Importing and linking the alignments

Start BEAUti with its Standard analysis template, then:

  1. Select File | Import Alignment and open data/passerines_pc1.nex.
  2. Select File | Import Alignment again and open data/passerines_pc2.nex.
  3. Confirm that each partition contains 20 taxa and 3,616 sites.
  4. Select both partitions with Shift-click.
  5. Select Unlink Site Models.
  6. Select Link Clock Models.
  7. Select Link Trees.

The partitions describe different codon positions, so each receives its own site model. They describe the same taxa and evolutionary history, so they share one tree. The basic analysis also gives both partitions one shared pattern of branch-to-branch rate variation.

Double-click the linked clock-model name and rename it passerinesClock. Double-click the linked tree name and rename it passerinesTree.

2.2 Defining the site models

Open the Site Model panel. For each partition:

  1. Select the partition.
  2. Select BEAST Model Test as its substitution model.
  3. Select estimate for Mutation Rate.

bModelTest averages the phylogenetic likelihood over supported nucleotide substitution models instead of conditioning the analysis on one selected model. Separate site models allow the two codon-position partitions to differ in base frequencies, substitution patterns, and among-site rate variation.

Estimating both mutation-rate multipliers allows the partitions to have different relative evolutionary rates. Their scale is relative to their weighted mean; the shared calibrated clock supplies the absolute time scale.

2.3 Defining the relaxed clock

Open the Clock Model panel and select Relaxed Clock Log Normal for passerinesClock. Retain -1 for Number Of Discrete Rates.

This uncorrelated lognormal relaxed clock draws the rate on each branch independently from one lognormal distribution. A strict clock would force one rate across all branches. Here, both codon-position partitions share the same branch-rate pattern while retaining the relative-rate multipliers defined in their site models.

The clock mean and the node ages cannot both be identified from contemporaneous sequences alone. The root-age calibration defined below supplies the absolute time information needed to estimate rates in substitutions per site per million years.

2.4 Defining the constrained taxon sets

Open the Priors panel. Select + Add Prior, choose MRCA prior, and create each of the following taxon sets:

Taxon set Select Number of taxa
Tyranni Every label beginning TYRANNI_ 3
Passeri Every label beginning PASSERI_ 16
Eupasseres Every label beginning TYRANNI_ or PASSERI_ 19
Passeriformes All labels 20

After creating the four MRCA priors, select monophyletic for each one. Monophyly of Eupasseres places the root between Acanthisitta chloris and the other 19 species.

2.5 Calibrating the root age

Find Passeriformes.prior in the Priors panel. Set its distribution to Log Normal, expand its options, and set:

Option Setting
Mean In Real Space Selected
M 5.0
S 0.5
Offset 43.0

This is an offset lognormal prior on the age of the most recent common ancestor of all 20 species. Its lower bound is 43 million years. Adding the real-space mean of 5 million years places the prior near 48 million years, with the distribution approximating the source estimate of 43–53 million years.

The calibration is a model input, not a result inferred from these alignments. It is a secondary calibration based on a fossil-informed estimate of crown Passeriformes from Luo and colleagues. The sequence data can update this prior, but every posterior divergence time remains conditional on it.

Workflow detail: What the calibration contributes
The alignment informs genetic branch lengths in expected substitutions per site. The calibration informs the age scale in millions of years. Combining the two lets BEAST estimate both dated node heights and absolute substitution rates.

An offset lognormal distribution is asymmetric. It prohibits ages below 43 million years while allowing a diminishing probability of substantially older ages. It does not fix the root age to 48 million years.

2.6 Defining the tree prior

In the Priors panel, set Tree.t:passerinesTree to Birth Death Model. Retain the remaining default priors for this exercise.

The birth-death tree prior models diversification through speciation and extinction. It contributes a probability distribution over tree topologies and branching times; it does not add observed characters to the alignment.

2.7 Defining the MCMC and output files

Open the MCMC panel and set Chain Length to 2000000.

Expand tracelog and set:

Option Setting
Log Every 200
File Name /home/student/projects/learning/scientific-julia/passerine-beast/results/passerines_LinkedClocks.log

Expand treelog and set:

Option Setting
Log Every 200
File Name /home/student/projects/learning/scientific-julia/passerine-beast/results/passerines_LinkedClocks.trees

Select File | Save As and save the analysis specification as:

/home/student/projects/learning/scientific-julia/passerine-beast/results/passerines_LinkedClocks.xml

The chain will attempt two million MCMC states and record a trace and tree every 200 states. This is the initial run length used in the source tutorial. It is not evidence that sampling will be adequate; that is assessed from the output.

2.8 Running the MCMC analysis

Close BEAUti and start the BEAST application.

  1. Select Choose File and open results/passerines_LinkedClocks.xml.
  2. Enter 20261001 as the random-number seed.
  3. Leave Allow overwriting of log files unselected.
  4. Retain the default computational options unless the computer has a configured BEAGLE installation.
  5. Select Run.

Confirm in the initial console output that BEAST loaded two alignments of 20 taxa, the bModelTest site models, passerinesClock, the birth-death tree prior, the four monophyly constraints, and the Passeriformes age prior.

After the run finishes normally, the results directory contains:

File Contents
passerines_LinkedClocks.xml Complete analysis specification.
passerines_LinkedClocks.log Sampled scalar parameters and probability densities.
passerines_LinkedClocks.trees Sampled rooted, time-scaled trees and their metadata.
passerines_LinkedClocks.xml.state Most recently stored MCMC state, used to resume an interrupted run.

Do not overwrite these files when starting an independent run.

2.9 Checking sampling in Tracer

Start Tracer and select File | Import Trace File. Open:

results/passerines_LinkedClocks.log

Set Burn-In to 10 percent provisionally. Inspect the trace plots and effective sample sizes for at least:

  • posterior, likelihood, and prior;
  • mrca.age(Passeriformes);
  • the relaxed-clock mean rate and coefficient of variation;
  • the first- and second-codon relative mutation rates; and
  • the birth-death diversification parameters.

Parameter names can include partition or model prefixes. In the source configuration, the clock summaries appear as rate.mean and rate.coefficientOfVariation, and the relative partition rates appear as BMT_mutationRate.1 and BMT_mutationRate.2.

For every important estimated quantity, confirm that:

  • the retained trace fluctuates around a stable region rather than showing a sustained trend;
  • the trace repeatedly traverses that region rather than remaining in long, distinct plateaus; and
  • the effective sample size (ESS) is at least 200.

Compare the posterior for mrca.age(Passeriformes) with the calibration prior. The mean clock rate is measured in substitutions per site per million years. The coefficient of variation describes relative rate variation among branches: a value near zero approaches a strict clock, while larger values indicate greater among-lineage rate heterogeneity.

If the initial transient extends beyond 10 percent, increase the burn-in. If an important ESS remains below 200, extend the chain or run a longer analysis and inspect it again. Record the final burn-in percentage. Do not construct the final summary tree until the retained samples are adequate.

Workflow detail: What MCMC contributes
BEAST does not return one optimized tree. Each retained state contains a tree, node times, branch rates, substitution-model indicators, and other parameter values. After convergence, the retained states approximate samples from their joint posterior distribution under the alignments, likelihood models, relaxed clock, calibration, topological constraints, tree prior, and parameter priors.

Tracer examines sampled scalar quantities. Stable scalar traces do not by themselves demonstrate that the chain explored tree space adequately. Independent runs provide an additional check.

2.10 Constructing a posterior summary tree

Start TreeAnnotator and set:

Option Setting
Burn in percentage The final percentage established in Tracer
Target tree type MAP (CCD0)
Node heights Common Ancestor heights
Input Tree File results/passerines_LinkedClocks.trees
Output File results/passerines_LinkedClocks.summary.tree

Select Run. CCD0 selects a tree topology from conditional clade distributions estimated from the posterior tree sample. Common-ancestor heights summarize the sampled ages associated with the clades on that tree. The output retains node annotations such as posterior clade probabilities and credible intervals for node ages.

2.11 Viewing the dated tree

Start FigTree and open:

results/passerines_LinkedClocks.summary.tree

Configure the display:

  1. Select Tree | Decreasing Node Order.

  2. Enable Scale Axis, expand its options, and enable Reverse axis so the tips are at time zero and older ages increase toward the root.

  3. Enable Node Labels and display posterior.

  4. Enable Node Bars and display height_95%_HPD.

  5. Export the figure as:

    results/passerines_LinkedClocks.summary.svg

The horizontal axis is time in millions of years because the analysis was calibrated on that scale. Node bars show 95% highest-posterior-density intervals for node ages. Node labels show posterior clade probabilities, not bootstrap percentages.

3 Follow-up workflows

3.1 Comparing independent runs

Create an independent replicate before treating the posterior summary as a final analysis.

  1. Open passerines_LinkedClocks.xml in BEAUti.
  2. Change the trace filename to passerines_LinkedClocks.rep2.log and the tree filename to passerines_LinkedClocks.rep2.trees.
  3. Save the XML as passerines_LinkedClocks.rep2.xml.
  4. Run it in BEAST with a different random-number seed.
  5. Import both .log files into Tracer.
  6. Select both runs and compare their marginal posterior densities after applying the same independently justified burn-in rule.

The two runs should converge on the same posterior distributions and each should provide adequate ESS values. Similar means without overlapping density shapes are not sufficient evidence of convergence.

After both runs pass the checks, open LogCombiner:

  1. Set File type to Tree Files.
  2. Add passerines_LinkedClocks.trees and passerines_LinkedClocks.rep2.trees.
  3. Enter the established burn-in percentage separately for each file.
  4. Write results/passerines_LinkedClocks.combined.trees.

Run TreeAnnotator on the combined file with Burn in percentage set to 0, because LogCombiner already removed the burn-in. Write:

results/passerines_LinkedClocks.combined.summary.tree

3.2 Assigning separate relaxed clocks to the partitions

The basic workflow gives the two codon-position partitions different relative rates but one shared pattern of rate variation among branches. The source tutorial also compares that model with two separate relaxed clocks.

Create a second analysis in BEAUti:

  1. Import passerines_pc1.nex and passerines_pc2.nex again.
  2. Select both partitions, then select Unlink Site Models, Unlink Clock Models, and Link Trees.
  3. Rename the shared tree passerinesTree.
  4. Select BEAST Model Test for both site models, but leave Mutation Rate unestimated. Each clock now supplies its partition’s absolute rate.
  5. Select Relaxed Clock Log Normal for each partition.
  6. Recreate the Tyranni, Passeri, Eupasseres, and Passeriformes taxon sets and enforce their monophyly.
  7. Apply the same offset lognormal root calibration to Passeriformes.prior.
  8. Select Birth Death Model for Tree.t:passerinesTree.
  9. Set the chain length to 2000000 and both log intervals to 200.

Use these filenames:

results/passerines_UnlinkedClocks.xml
results/passerines_UnlinkedClocks.log
results/passerines_UnlinkedClocks.trees

Run and diagnose the analysis in the same way as the linked-clock analysis. The output now contains separate mean rates and coefficients of variation for the first- and second-codon partitions. Compare their posterior distributions, not only their point estimates. Greater flexibility does not by itself make the unlinked-clock model preferable; the biological interpretation and model comparison must justify the extra parameters.

4 Recording the analysis

Preserve the following with the results:

  • the two original NEXUS alignments;
  • every BEAST XML file;
  • the .log, .trees, and .xml.state files from each run;
  • the software and package versions;
  • the random-number seed for each run;
  • the burn-in removed from each run and the diagnostic evidence supporting it;
  • the combined tree sample and TreeAnnotator settings; and
  • the annotated summary tree and exported figure.

The XML records the executable model specification. The alignment and XML are both required to reproduce the likelihood, clock, calibration, constraints, priors, operators, and output configuration.
