Phylogenetic inference tools – distance-based inference with MEGA

Author

Jeet Sukumaran

MEGA estimates evolutionary distances and uses them to infer neighbor-joining, minimum-evolution, and UPGMA trees. The graphical interface supports interactive analysis and inspection. MEGA-CC exposes the same analyses through the megacc command for scripted and repeated execution.

Distance-based inference has two distinct stages:

  1. MEGA converts each pair of aligned sequences into one evolutionary-distance estimate.
  2. A tree-building method uses the resulting distance matrix to infer a topology and branch lengths.

The distance model, site subset, and missing-data treatment therefore affect the matrix before the tree-building algorithm begins.

1 Installation and interfaces

Download MEGA for the operating system from the MEGA website. The MEGA-GUI and MEGA-CC downloads both contain the graphical interface and the command-line computational core. The graphical interface is required to create MEGA Analysis Options (.mao) files, so the MEGA-GUI download is the usual choice.

MEGA provides three relevant interfaces:

Interface Purpose
MEGA Analyze mode Opens data, runs analyses interactively, and displays results.
MEGA Prototype mode Defines an analysis without running it and saves the settings in a .mao file.
MEGA-CC Runs the analysis recorded in a .mao file from the megacc command.

Display the MEGA-CC command-line help after installation:

megacc -h

Record the MEGA version shown under Help | About MEGA with the analysis results. The menu paths and command-line examples below follow MEGA 12.

2 Input requirements and conversion

Distance estimation from sequence data requires a multiple-sequence alignment, not raw unaligned sequences. Before inference, confirm that:

  • every sequence represents homologous characters and has the same aligned length;
  • every taxon has a unique label;
  • labels are compact and avoid whitespace and Newick punctuation such as parentheses, commas, colons, and semicolons;
  • the declared data type matches the alignment;
  • protein-coding annotations and codon positions, when used, match the alignment coordinates;
  • the selected sites contain enough comparable characters for every required pairwise distance; and
  • alignment uncertainty has been evaluated before the alignment is treated as fixed input.

MEGA can convert aligned FASTA, NEXUS, PHYLIP, CLUSTAL, and several other text formats to its native .meg format. In the graphical interface, select File | Convert File Format to MEGA, choose the source alignment, confirm the data type and special characters, and save the converted file.

For FASTA input, MEGA uses the first word after > as the sequence name during conversion. Labels that differ only after the first whitespace therefore collide. Normalize and verify the labels before inference.

Keep the original alignment and the converted .meg file together. The converted file is analysis input, not a replacement for the curated source alignment.

3 Distance-based tree-building methods

MEGA provides three principal distance-based methods:

Method Result and principal assumption
Neighbor joining (NJ) Constructs one unrooted tree without assuming equal evolutionary rates among lineages. It is the usual starting method for distance-based exploration.
Minimum evolution (ME) Searches from an initial tree, normally an NJ tree, for a topology with a smaller sum of branch lengths. MEGA uses close-neighbor interchange, so the search does not guarantee the global minimum. The result is unrooted.
UPGMA Builds a rooted ultrametric tree under the assumption that evolutionary rates are constant among lineages. Use it for phylogenetic inference only when that assumption is defensible.

MEGA may display an NJ or ME tree with a root-like orientation. That display does not identify a biological root. Root the exported tree according to the study design, such as with a justified outgroup, and record that separate decision.

4 A standard neighbor-joining analysis

Open the aligned .meg file with Data | Open a File/Session. Select Phylogeny | Construct/Test Neighbor-Joining Tree.

The Analysis Preferences window contains the complete analysis definition. For an illustrative nucleotide analysis, set:

Option Setting
Test of Phylogeny Bootstrap method
No. of Bootstrap Replications 1000
Substitutions Type Nucleotide
Model/Method Tamura-Nei model
Substitutions to Include Transitions and transversions
Rates among Sites Uniform rates
Gaps/Missing Data Treatment Complete deletion
Codon Positions All positions represented by the alignment

These settings define an example, not a universal default. The Tamura-Nei distance corrects for multiple substitutions while allowing unequal nucleotide frequencies and different transition rates. Uniform rates assume no among-site rate variation. Complete deletion uses the same gap-free, unambiguous columns for every pairwise distance. Each assumption must be evaluated for the data under study.

Select Compute. MEGA opens the result in Tree Explorer. Before interpreting the topology:

  1. Open the Tree Explorer information box and confirm the number of taxa, the distance model, the site subset, and the missing-data treatment.
  2. Inspect the original NJ tree and its branch lengths.
  3. Inspect the bootstrap consensus and the support values on the original topology.
  4. Confirm that the analysis contains every expected taxon and no duplicate or truncated labels.
  5. Export the analysis summary from File | Export Analysis Summary.
  6. Export the tree from File | Export Current Tree (Newick) and give it a .nwk extension.

Save a native Tree Explorer session when the interactive display must be reopened. Preserve the Newick tree for exchange with other software and preserve the text summary as the record of the analysis settings.

5 Repeating an analysis with MEGA-CC

MEGA-CC requires a .mao file created by MEGA’s graphical interface. The file records both the requested analysis and its settings.

Create the file as follows:

  1. Select Prototype in the main MEGA window.
  2. Select the data type, such as Nucleotide.
  3. Select Phylogeny | Construct/Test Neighbor-Joining Tree.
  4. Enter the distance model, site subset, missing-data treatment, bootstrap procedure, and replicate count.
  5. Select Save Settings and save the file as neighbor-joining-tamura-nei.mao.

Do not construct a .mao file from undocumented text copied from another MEGA version. Generate it in the installed MEGA version, inspect the displayed options, and preserve it with the analysis.

The megacc parameters supply the saved analysis, input alignment, and output prefix:

Parameter Meaning
-a neighbor-joining-tamura-nei.mao Reads the analysis and its settings from the .mao file.
-d alignment.meg Reads the aligned sequence data from the .meg file.
-o alignment_nj_tn93 Writes results with the supplied path and prefix.

Set the paths and construct the command in Julia:

REPL
julia> project_dir = "/home/student/projects/learning/scientific-julia/phylogenetic-inference";

julia> alignment_path = joinpath(project_dir, "data", "processed", "alignment.meg");

julia> analysis_options_path = joinpath(project_dir, "config", "neighbor-joining-tamura-nei.mao");

julia> results_dir = joinpath(project_dir, "results");

julia> mkpath(results_dir);

julia> output_prefix = joinpath(results_dir, "alignment_nj_tn93");

julia> mega_command = `megacc -a $analysis_options_path -d $alignment_path -o $output_prefix`;

joinpath constructs paths with the separator used by the operating system. Interpolation with $ inserts each path as one argument in the command. Constructing the Cmd value does not start MEGA-CC.

Run the command and wait for it to finish:

REPL
julia> run(mega_command)

For an output prefix of alignment_nj_tn93, a neighbor-joining analysis normally produces:

File Contents
alignment_nj_tn93.nwk Inferred tree in Newick format.
alignment_nj_tn93_summary.txt Input details, analysis settings, numerical summaries, warnings, and errors.

Confirm that both files exist, then read the summary in Julia:

REPL
julia> tree_path = output_prefix * ".nwk";

julia> summary_path = output_prefix * "_summary.txt";

julia> isfile(tree_path), isfile(summary_path)
(true, true)

julia> summary_text = read(summary_path, String);

julia> print(summary_text)

read(summary_path, String) reads the complete text file and returns it as a String. Inspect the summary before using the tree. A process that writes an output file can still report warnings that materially affect the result.

Workflow alternate: Running the neighbor-joining analysis from the shell

The same megacc invocation can be run directly from the shell:

Shell
megacc \
    -a config/neighbor-joining-tamura-nei.mao \
    -d data/processed/alignment.meg \
    -o results/alignment_nj_tn93

Inspect the summary after the process finishes:

Shell
less results/alignment_nj_tn93_summary.txt

6 Choosing an evolutionary-distance model

The distance model determines how observed character differences become estimates of evolutionary change. Common nucleotide choices include:

Model or method Principal features
p-distance Uses the observed proportion of differing sites. It does not correct for multiple substitutions at the same site.
Jukes-Cantor Corrects for multiple substitutions under equal nucleotide frequencies and equal substitution rates.
Kimura 2-parameter Distinguishes transitions from transversions while retaining equal equilibrium nucleotide frequencies.
Tamura 3-parameter Distinguishes transition classes and accommodates unequal GC content under its stated assumptions.
Tamura-Nei Accommodates unequal nucleotide frequencies and distinct transition and transversion rates.
Maximum composite likelihood Estimates Tamura-Nei distances jointly through a composite-likelihood procedure and offers additional rate and pattern options.

A more parameter-rich correction is not automatically more appropriate. Examine sequence composition, divergence, saturation, the amount of information in the alignment, and the assumptions of the available models. State the exact distance model rather than reporting only “neighbor joining,” because the same tree-building algorithm can receive substantially different distance matrices.

Some models permit gamma-distributed rate variation among sites. MEGA then requires a gamma shape parameter. Record how that value was estimated; do not transfer a value from an unrelated data set.

For amino-acid data, select Amino Acid under Substitutions Type and choose an amino-acid distance model. For protein-coding nucleotide data, verify the genetic code and codon-position annotations before selecting nucleotide, synonymous–nonsynonymous, or translated amino-acid distances.

7 Gaps and missing data

The missing-data rule determines which alignment columns contribute to each distance:

Treatment Effect
Complete deletion Removes every site that contains a gap or missing state in any taxon. Every distance uses the same retained columns, but a few incomplete sequences can discard much of the alignment.
Pairwise deletion Removes incomplete sites separately for each sequence pair. It retains more observations, but different entries in the distance matrix may be based on different site sets.
Partial deletion Retains sites that meet a specified coverage threshold. The threshold must be stated and justified.

Inspect how many sites remain under the selected rule. Pairwise deletion can produce a distance matrix whose entries have very different precision and site composition. Complete deletion can leave too little data. Partial deletion moves the decision into the coverage threshold rather than removing it.

If MEGA reports that no common sites are available for a sequence pair, identify the taxa and columns responsible. Do not change to pairwise deletion only to silence the error without evaluating the resulting site sets.

8 Minimum-evolution analyses

Select Phylogeny | Construct/Test Minimum Evolution Tree to run a minimum-evolution analysis. Specify the same distance-model, site-subset, missing-data, and support decisions used for the corresponding NJ analysis when the purpose is to compare the tree-building criteria.

MEGA starts the search from an NJ tree and applies close-neighbor interchange. The search level controls how extensively the program examines neighboring topologies. Record the search level, initial-tree method, distance model, gap treatment, and bootstrap settings.

Generate a separate .mao file for command-line execution, such as minimum-evolution-tamura-nei.mao, and use a distinct output prefix. Do not reuse the NJ .mao file and rename its output: the requested tree-building method is stored inside the options file.

9 UPGMA analyses

Select Phylogeny | Construct/Test UPGMA Tree only when a constant rate of evolution among lineages is a defensible assumption. UPGMA produces a rooted ultrametric tree because that rate assumption makes every tip equidistant from the root.

A rooted display is not, by itself, evidence for UPGMA’s molecular-clock assumption. Evaluate rate constancy independently and report the evidence used. If the assumption is not supported, NJ or ME provides an unrooted distance-based analysis without imposing the UPGMA clock structure.

As with NJ and ME, save a method-specific .mao file and use a distinct output prefix.

10 Bootstrap support

MEGA’s bootstrap test resamples alignment columns with replacement, recalculates the distance matrix, and reconstructs a tree for each replicate. The value on an internal branch is the percentage of replicate trees containing the corresponding split.

Use enough replicates for the reported percentages to stabilize; 1,000 replicates is a common starting point. Preserve the replicate count in the .mao file and analysis summary. If the interface exposes a starting random seed for the selected analysis, set and record it. Also record the MEGA version and computing platform because a seed alone does not guarantee identical results across software versions or systems.

Bootstrap percentages are not posterior probabilities and do not measure the probability that a clade is true. They describe repeatability under resampling, conditional on the alignment, distance model, missing-data rule, and tree-building method.

The original inferred tree and the bootstrap consensus answer different questions. MEGA does not assign meaningful branch lengths to a bootstrap consensus tree when unsupported splits collapse. Use branch lengths from the original tree and support values to describe the repeatability of its splits.

11 Output and reporting

Preserve the following materials for every analysis:

  • the original curated alignment;
  • the converted .meg input file;
  • the .mao analysis-options file;
  • the exported .nwk tree;
  • the analysis-summary text file;
  • the native Tree Explorer session when interactive formatting or inspection must be reproduced; and
  • the MEGA version and operating-system information.

The .mao file records settings, but it does not replace the input data or result summary. The Newick file records the tree, but it does not record the bootstrap replicate count or every analysis assumption. Keep the files together under a unique analysis name.

Report at least:

  • the MEGA version;
  • the tree-building method;
  • the distance model and its parameter settings;
  • the character type and included site or codon subsets;
  • the among-site rate treatment;
  • the gap and missing-data treatment;
  • the number of retained sites;
  • the bootstrap procedure and replicate count;
  • the ME search settings, if applicable; and
  • the rooting procedure applied after inference, if applicable.

12 Operational checklist

  1. Curate and inspect the multiple-sequence alignment.
  2. Normalize and verify unique taxon labels.
  3. Convert the alignment to .meg format and confirm its data type and annotations.
  4. Choose the tree-building method independently of the evolutionary-distance model.
  5. Specify the distance model, rate treatment, site subset, and missing-data treatment.
  6. Set the bootstrap procedure and replicate count when branch support is required.
  7. Review every setting in the Analysis Preferences window before computation.
  8. Save a method-specific .mao file for scripted or repeated execution.
  9. Inspect the analysis summary and resolve relevant warnings or errors.
  10. Export the tree in Newick format and preserve the summary, options file, and input data.
  11. Treat NJ and ME results as unrooted until a separate rooting decision is applied.
  12. Report the settings that defined both the distance matrix and the tree-building procedure.
