Phylogenetic inference tools – RAxML-NG

Author

Jeet Sukumaran

RAxML-NG infers maximum-likelihood phylogenies from aligned molecular or discrete-character data. A typical analysis checks the alignment, selects or specifies an evolutionary model, searches for the maximum-likelihood tree, estimates branch support, and writes the resulting trees in Newick format.

The commands below use RAxML-NG 2.x. Automatic model selection and the adaptive tree-search defaults described here are not available in the same form in RAxML-NG 1.x.

1 Installation and command-line help

Download a current binary from the RAxML-NG releases, or install the Bioconda package:

conda install -c bioconda raxml-ng

Confirm the installed version and display the available commands and parameters:

raxml-ng --version
raxml-ng --help

Record the version reported by --version with the analysis results. If automatic model selection is required, confirm that the installed version is 2.0 or later.

2 Input requirements and validation

RAxML-NG requires a multiple-sequence alignment, not raw unaligned sequences. FASTA and PHYLIP are the usual text formats; the program also accepts its binary RAxML Binary Alignment format.

Before starting an analysis, confirm that:

  • every sequence represents homologous characters and has the same aligned length;
  • every taxon has a unique label;
  • labels avoid spaces and Newick punctuation such as parentheses, commas, colons, and semicolons;
  • the alignment contains the intended character type;
  • partition coordinates, if used, are one-based and match the alignment; and
  • constant sites remain present unless the sampling process deliberately retained only variable sites.

Check a nucleotide alignment before a full analysis:

raxml-ng \
    --check \
    --msa alignment.fasta \
    --model GTR+G \
    --prefix alignment_check

--check validates the alignment and identifies problems such as duplicate taxon names, sequences or columns containing only undetermined characters, and other incompatible input. If a corrected or reduced alignment is written, either use that file or correct the original data before inference.

For a large alignment, parse it once into RAxML-NG’s compressed binary format:

raxml-ng \
    --parse \
    --msa alignment.fasta \
    --model GTR+G \
    --prefix alignment_parsed

The main output is alignment_parsed.raxml.rba. It can replace the text alignment in later commands and usually loads more quickly:

raxml-ng \
    --search \
    --msa alignment_parsed.raxml.rba \
    --prefix alignment_search

The binary alignment contains the model and partition definitions used during parsing. RAxML-NG therefore ignores a separate --model argument when reading an .raxml.rba file. Reparse the original text alignment to change its model or partitions.

3 A standard analysis

The following RAxML-NG 2.x command selects a nucleotide model, searches for a maximum-likelihood tree, runs nonparametric bootstrap replicates, and maps Felsenstein bootstrap proportions onto the best tree:

raxml-ng \
    --all \
    --msa alignment.fasta \
    --model DNA \
    --bs-trees 'autoMRE{1000}' \
    --bs-metric fbp \
    --threads 'auto{8}' \
    --seed 20260921 \
    --prefix alignment_run1

The parameters have the following meanings:

Parameter Meaning
--all Performs model fitting and maximum-likelihood tree search, bootstrap inference, and support mapping in one run.
--msa alignment.fasta Reads the multiple-sequence alignment from alignment.fasta.
--model DNA Identifies nucleotide data and invokes MOOSE automatic model selection. MOOSE uses the Bayesian information criterion by default. Use AA for amino-acid data or supply a fixed model string or partition file.
--bs-trees 'autoMRE{1000}' Uses the majority-rule extended convergence test to stop bootstrapping when the replicate trees have converged, with a maximum of 1,000 replicates. Inspect the log to confirm whether convergence was reached.
--bs-metric fbp Calculates classical Felsenstein bootstrap proportions. This is the default metric, but stating it explicitly records the procedure in the command.
--threads 'auto{8}' Autotunes parallel execution without using more than eight CPU threads. The quotes preserve the braces in common shells.
--seed 20260921 Sets the pseudorandom-number seed. Any fixed non-negative integer may be used. Record the software version and computing environment because a seed alone does not guarantee identical results across versions or platforms.
--prefix alignment_run1 Writes output files with the prefix alignment_run1. Use a distinct prefix for every analysis.

The best tree with mapped support values is alignment_run1.raxml.support. The maximum-likelihood tree without support labels is alignment_run1.raxml.bestTree.

4 Analysis commands

RAxML-NG selects one main analysis command per invocation:

Command Operation
--search Searches for maximum-likelihood tree topologies. This is the default when no command is given, but stating it explicitly makes the workflow clear.
--all Combines tree search, bootstrapping, and support mapping.
--fast Performs a reduced, early-stopping tree search from one parsimony tree. Use it for exploratory work rather than as a replacement for a full search without evaluating the trade-off.
--allfast Combines the fast search with the Educated Bootstrap Guesser support procedure.
--moose Performs model selection without a subsequent full topology search.
--bootstrap Infers bootstrap replicate trees without performing the main maximum-likelihood search.
--support Maps support from an existing collection of replicate trees onto a reference tree.
--evaluate Optimizes model parameters and branch lengths on a supplied fixed topology.
--check Validates an alignment and removes empty rows or columns when necessary.
--parse Validates and compresses an alignment into the binary .raxml.rba format.
--rfdist Calculates pairwise Robinson–Foulds distances among trees in a Newick file.

5 Model selection and model strings

Run MOOSE model selection without a subsequent full search:

raxml-ng \
    --moose \
    --msa alignment.fasta \
    --data-type DNA \
    --prefix alignment_models

The selected model is written to alignment_models.raxml.moose.bestModel. Use it directly in a later search:

raxml-ng \
    --search \
    --msa alignment.fasta \
    --model alignment_models.raxml.moose.bestModel \
    --threads 'auto{8}' \
    --seed 20260921 \
    --prefix alignment_search

The accompanying alignment_models.raxml.rba file already contains the selected model and can instead be supplied with --msa without a --model argument.

MOOSE uses BIC by default. Select another supported information criterion when required by the analysis design:

raxml-ng \
    --moose \
    --msa alignment.fasta \
    --data-type DNA \
    --moose-options criterion=AICc \
    --prefix alignment_models_aicc

Alternatively, provide a fixed model directly:

raxml-ng \
    --all \
    --msa alignment.fasta \
    --model GTR+G4+FO \
    --bs-trees 1000 \
    --threads 8 \
    --seed 20260921 \
    --prefix alignment_gtr_g4_fo

A RAxML-NG model string combines a substitution model with optional components:

Component Meaning
GTR, HKY, JC Examples of nucleotide substitution models.
LG, WAG, JTT Examples of amino-acid exchangeability models.
+F Uses empirical state frequencies calculated from the alignment.
+FO Optimizes state frequencies by maximum likelihood.
+I Estimates a proportion of invariant sites.
+G4 Models among-site rate variation with a discrete gamma distribution and four rate categories. +G also defaults to four categories.
+R4 Models among-site rate variation with four FreeRate categories.
+ASC_LEWIS Applies Lewis ascertainment-bias correction to data from which constant characters were deliberately excluded.

Do not add model components by convention alone. Use MOOSE or provide a biological and statistical reason for fixing a model. Model-string syntax and defaults can differ among phylogenetic programs, so do not copy a model string from another program without checking its RAxML-NG meaning.

6 Partitioned alignments

Partition a concatenated alignment when defined site sets, such as genes or codon positions, require separate evolutionary models. A partition file named partitions.txt can contain:

GTR+G4+FO, gene1_pos1 = 1-900\3
GTR+G4+FO, gene1_pos2 = 2-900\3
GTR+G4+FO, gene1_pos3 = 3-900\3
GTR+G4+FO, gene2 = 901-1500

The expression 1-900\3 selects sites 1, 4, 7, and so forth through site 898. The other two expressions select the second and third codon positions.

Run the partitioned analysis with proportional branch lengths:

raxml-ng \
    --all \
    --msa concatenated.fasta \
    --model partitions.txt \
    --brlen scaled \
    --bs-trees 'autoMRE{1000}' \
    --threads 'auto{8}' \
    --seed 20260921 \
    --prefix concatenated_partitioned

The branch-length linkage modes are:

Parameter Partition model
--brlen linked Uses one shared branch length for each edge across all partitions.
--brlen scaled Uses proportional branch lengths: partitions share the relative edge-length pattern but have separate overall rate scalers. This is the default.
--brlen unlinked Estimates an independent branch length for every edge in every partition. This introduces many more parameters.

For automatic per-partition model selection in RAxML-NG 2.x, prefix the partition filename with auto=:

raxml-ng \
    --search \
    --msa concatenated.fasta \
    --model auto=partitions.txt \
    --brlen scaled \
    --prefix concatenated_models_search

7 Starting trees, constraints, and fixed trees

These parameters have distinct effects:

Parameter Effect
Omit --tree Uses the RAxML-NG 2.x adaptive procedure to choose starting trees based on predicted alignment difficulty.
--tree 'pars{10},rand{10}' Runs searches from ten randomized parsimony trees and ten random trees.
--tree start.tree Starts the search from the supplied Newick tree. The topology may change during the search.
--tree-constraint constraint.tree Restricts the topology search to trees compatible with the supplied, possibly incomplete, constraint tree.
--evaluate --tree fixed.tree Keeps the supplied topology fixed while optimizing its branch lengths and free model parameters.
--outgroup TaxonA,TaxonB Draws the reported tree with the named taxa on the outgroup side. This is an output-orientation option, not statistical evidence about the root.

Use constraints only when they represent an explicit analysis assumption. A starting tree is not a constraint, and maximum likelihood under the usual reversible models infers an unrooted tree.

8 Bootstrap support

Use a fixed number of classical bootstrap replicates when the analysis requires a predetermined count:

raxml-ng \
    --all \
    --msa alignment.fasta \
    --model DNA \
    --bs-trees 1000 \
    --bs-metric fbp \
    --prefix alignment_fbp

For large trees, calculate both Felsenstein bootstrap proportions and transfer bootstrap expectation values from the same replicate trees:

raxml-ng \
    --all \
    --msa alignment.fasta \
    --model DNA \
    --bs-trees 'autoMRE{1000}' \
    --bs-metric fbp,tbe \
    --prefix alignment_fbp_tbe

When multiple support metrics are requested, RAxML-NG writes separate supported trees such as .raxml.supportFBP and .raxml.supportTBE. Support values are conditional on the alignment, model, search, and resampling procedure; they are not posterior probabilities and do not establish a root.

Map support from previously generated replicate trees onto an existing reference tree:

raxml-ng \
    --support \
    --tree alignment_run1.raxml.bestTree \
    --bs-trees alignment_run1.raxml.bootstraps \
    --bs-metric fbp,tbe \
    --prefix alignment_support

9 CPU and memory use

On a scheduler or shared computer, never exceed the allocated CPU count:

--threads 8

Use bounded autotuning when the efficient thread count is unknown:

--threads 'auto{8}'

--workers N controls how many independent tree searches run concurrently within the available parallel resources. The default auto setting is usually appropriate. Increasing the worker count does not increase the CPU allocation and can reduce the threads available to each search.

The --parse command reports memory and thread-count guidance for the supplied alignment and model. RAxML-NG has no general command-line memory cap comparable to a scheduler memory request; request sufficient memory from the scheduler and inspect the parse estimate before submitting a large job.

10 Output files

For --prefix alignment_run1, the principal files are:

File Contents
alignment_run1.raxml.support Best maximum-likelihood tree with Felsenstein bootstrap support.
alignment_run1.raxml.bestTree Best-scoring maximum-likelihood tree without mapped support values.
alignment_run1.raxml.mlTrees Resulting maximum-likelihood tree from each starting-tree search.
alignment_run1.raxml.bootstraps Tree inferred from each bootstrap replicate.
alignment_run1.raxml.bestModel Optimized model specification and parameter estimates for the best tree.
alignment_run1.raxml.startTree Starting trees used for the maximum-likelihood searches.
alignment_run1.raxml.log Program version, exact command, input summary, settings, warnings, progress, likelihoods, and completion status.
alignment_run1.raxml.ckp Intermediate checkpoint used to resume an interrupted run; normally removed after successful completion.
alignment_run1.raxml.rba Compressed binary representation of the alignment and its partitions.

Read the log before using the tree:

less alignment_run1.raxml.log

Confirm that:

  • the program completed normally;
  • the data type, alignment dimensions, and partitions are correct;
  • the selected or fixed model is the intended one;
  • the number of searches and bootstrap replicates is adequate;
  • autoMRE convergence was reached when bootstopping was requested;
  • warnings about duplicate sequences, missing data, numerical behavior, or constraints have been evaluated; and
  • the best log-likelihood, seed, program version, and exact command have been recorded.

11 Checkpoints and repeated analyses

RAxML-NG periodically writes the .raxml.ckp checkpoint. If a run is interrupted, rerun the same command with the same inputs and prefix; RAxML-NG resumes from the checkpoint.

A completed result prevents accidental overwriting. Use a new prefix for another analysis. The --redo parameter ignores the existing checkpoint, deletes or overwrites result files for that prefix, and starts from the beginning; use it only when the existing result is no longer needed.

To request a specified collection of independent searches in one run, use an explicit starting-tree set such as:

--tree 'pars{10},rand{10}'

Compare the final likelihoods in .raxml.mlTrees and .raxml.log. Retain the highest-likelihood result rather than selecting a tree by its support values.

12 Operational checklist

  1. Prepare and inspect the aligned input data.
  2. Run --check; use --parse for large alignments.
  3. Select the data type and partition scheme.
  4. Use MOOSE model selection or state a fixed model.
  5. Choose the tree-search and branch-support procedures.
  6. Set a fixed seed, allocated thread limit, and unique prefix.
  7. Save the exact command, RAxML-NG version, alignment, model, and partition file.
  8. Read the .raxml.log file and resolve relevant warnings.
  9. Preserve the supported tree, best tree, bootstrap trees, model file, log, and binary alignment.
  10. Root the inferred tree according to the biological study design and document that decision.
  11. Report the software version, model-selection criterion or fixed model, partition branch-length mode, tree-search settings, support metric, and replicate or convergence rule.
  12. Cite RAxML-NG and any feature-specific methods identified by the software documentation.
