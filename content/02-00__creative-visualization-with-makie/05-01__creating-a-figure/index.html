1 The Makie visualization ecosystem

TipOn the name: Makie

The name “Makie” is derived from the Japanese word, 蒔絵 (*Maki-e”), which translates literally to “sprinkled picture”.

The name Makie (we pronounce it Mah-kee) is derived from the japanese word Maki-e, which is a technique to sprinkle lacquer with gold and silver powder. Data is the gold and silver of our age, so let’s spread it out beautifully on the screen!

— Makie README

1.1 What is Makie?

Makie is a visualization framework for Julia. It provides abstractions (types and functions) to compose 2D and 3D static, interactive, and animated figures. Makie’s abstractions support higher level geometric and data visualization semantics for us to express and communicate our ideas, concepts, and data graphically, decoupled from the lower level software, operating system, and hardware computing stack that renders these semantics into display pixels or digital media files. That is, we can use Makie to compose our figure in terms of the fundamental Euclidean geometries (points, lines, polygons etc.) or higher-order data-centric plots (scatter plots, line plots, histograms, etc.), while a Makie backend will convert our figure composition into pixels, vector graphics, or an interactive display.

1.2 Installing Makie

We typically do not install Makie directly, but rather install (and use) a particular Makie backend, such as CairoMakie, GLMakie, or WGLMakie. A Makie backend is the infrastructure that handles translating our ideas, thoughts, concepts, and data expressed in terms of geometries, statistical plots, aesthetics (color, styling), and so on into instructions that will result in our composition being rendered to a display or a file. We need to provision a Julia environment with a Makie backend for Makie to be available to Julia programs running in that environment. We do this by installing the Makie backend package into the environment using the standard Julia package management system. In this series, we will be using the GLMakie backend, as it is more REPL-flow friendly and also to take advantage of Makie’s interactivity features when we need to.

using Pkg
Pkg.add("GLMakie")

As with all package installations, we only need to do this once for any particular backend and any particular environment.

1.3 Loading and activating a backend

To have the Makie abstractions and functionality available to Julia programs and other packages that depend on them in a particular environment, we typically load a particular backend, which re-exports (or implements) the Makie interface, rather than the Makie package directly:

using GLMakie

Note that When using packages from the broader Makie ecosystem, we have to explicitly load the backend we want to use for the other packages to work.

For example:

using GLMakie
using PhyloMakie
using PhyloPicMakie
using GeoMakie

2 Composing a Makie Figure

We use Makie to express and communicate visual concepts by building them up in a series of nested layers: A Figure instance tracks a collection of Axis instances, each of which tracks a collection of Plot instances.

A typical Makie visualization looks like:


# Set up the figure
fig = Figure()

# Set up the plotting frame
ax = Axis(fig[x, y]; ...)

# Create the plots
plotting_function1!(ax, ....)
plotting_function2!(ax, ....)
...

# Display/save plot
....

2.1 The Figure type

A Makie composition starts by creating a new Figure instance:

figure1 = Figure()

We use instances of the Makie Figure type as the top-level container for our entire composition, to track the layout of one or more Axis instance The Figure type does not itself store any direct plotting data, but rather tracks layout data for one or more instances of the Axis type, each of each serves as a self-contained drawing region.

2.2 The Axis type

We create an Axis instance by passing its location within a Figure.

ax1 = Axis(figure1[1, 1])
Makie.Axis with 0 plots:

Each instance of the Axis type tracks a distnct collection of Plot instances, each of which, in turn represent one sets of plotting or drawing data.

A Figure organizes our composition into a grid, in which particular grid positions are referenced by [row, column] indexing. Here we are assigning our new Axis object into the first grid position of figure1: figure1[1, 1].

The Figure object creates space for the grid position as we refer to them, so, if we do not add any Axis into any other grid position, our figure1 will be a single grid cell with the ax1. One figure can contain several axes, and one axis can contain several plot objects. A plot object is one visual representation inside that composition.

As can be seen, our new Axis has 0 plots in it. An Axis can contain multiple plot objects, all positioned within its coordinate system. We build up the visual content of our composition by adding Plot objects to our Axis, ax1, just as we build up a drawing by adding marks and shapes to a canvas.

2.3 The Plot

Plot objects are collections of visual elements we place on our figurative canvas. A Plot object can represent something as simple as a single point, line, polygon, or something more complex such as a collections of points, lines, line segments, or histograms or surfaces.
