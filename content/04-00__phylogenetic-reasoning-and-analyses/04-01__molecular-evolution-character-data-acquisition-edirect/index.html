Jeet Sukumaran

1 Install EDirect

NCBI Entrez Direct (EDirect) provides programs for searching and retrieving records from the Entrez databases. EDirect requires a Unix-compatible shell. On Windows, use Windows Subsystem for Linux (WSL).

Run the installer from the system shell:

$ sh -c "$(curl -fsSL https://ftp.ncbi.nlm.nih.gov/entrez/entrezdirect/install-edirect.sh)"

The $ marks the shell prompt and is not part of the command. The installer places EDirect in ~/edirect and offers to add that directory to PATH. Accept the offer, then restart the terminal if instructed.

Confirm that the shell finds each program used below:

$ command -v esearch epost efetch xtract
/home/student/edirect/esearch
/home/student/edirect/epost
/home/student/edirect/efetch
/home/student/edirect/xtract

$ esearch -version
26.2

The path contains the local user name. The version may be newer than the one shown here. The EDirect release notes document version changes.

Create a project directory and start Julia with a project environment:

$ mkdir -p bear-edirect-project
$ cd bear-edirect-project
$ julia --project=.

Add DataFrames.jl from Julia’s package mode:

julia> ]

pkg> add DataFrames

Press Backspace at an empty pkg> prompt to return to julia>.

Load the required names and create the raw-data directory:

julia> using DataFrames: DataFrame, leftjoin, nrow, select, unstack

julia> import Dates

julia> raw_dir = joinpath("data", "raw")
"data/raw"

julia> mkpath(raw_dir)
"data/raw"

julia> pwd()
"/home/student/bear-edirect-project"

2 Run external programs from Julia

Julia’s external-program interface represents a command as a value. Julia launches the program directly; it does not place a shell between Julia and the program.

2.1 Construct a command

Backticks construct a Cmd object without running it:

julia> version_command = `esearch -version`
`esearch -version`

julia> typeof(version_command)
Cmd

julia> collect(version_command)
2-element Vector{String}:
 "esearch"
 "-version"

Each element of the command is 1 program argument.

2.2 Run a command

run starts the program and leaves its standard output connected to the terminal:

julia> run(version_command);
26.2

A command that exits with a nonzero status causes run to throw a ProcessFailedException. The success function runs a command and reports its exit status as a Boolean:

julia> success(`esearch -version`)
true

2.3 Capture standard output

read runs the program and returns its complete standard output. A terminal newline remains part of the captured string:

julia> version_text = read(version_command, String)
"26.2\n"

julia> ncodeunits(version_text)
5

readchomp removes 1 trailing line ending:

julia> edirect_version = readchomp(version_command)
"26.2"

2.4 Interpolate arguments

$ interpolates Julia values into a Cmd. A string remains 1 argument even when it contains spaces or characters that a shell would interpret:

julia> organism_name = "Ailuropoda melanoleuca"
"Ailuropoda melanoleuca"

julia> organism_query = "\"$(organism_name)\"[Scientific Name]"
"\"Ailuropoda melanoleuca\"[Scientific Name]"

julia> search_command = `esearch -db taxonomy -query $organism_query`
`esearch -db taxonomy -query '"Ailuropoda melanoleuca"[Scientific Name]'`

julia> collect(search_command)
5-element Vector{String}:
 "esearch"
 "-db"
 "taxonomy"
 "-query"
 "\"Ailuropoda melanoleuca\"[Scientific Name]"

Interpolating a collection supplies several arguments:

julia> requested_fields = ["TaxId", "ScientificName", "Rank"];

julia> field_command = `xtract -pattern Taxon -element $requested_fields`
`xtract -pattern Taxon -element TaxId ScientificName Rank`

Shell operators such as | and > do not connect or redirect programs inside Julia backticks. Julia values, IOBuffer, read, write, and pipeline provide those operations.

2.5 Supply standard input

An IOBuffer presents a Julia string as an input stream. The following pipeline call attaches that stream to the standard input of exactly 1 external program:

julia> sample_xml = """
       <Rows>
         <Row><taxon>Ursidae</taxon><rank>family</rank></Row>
         <Row><taxon>Selachii</taxon><rank>superorder</rank></Row>
       </Rows>
       """;

julia> sample_tsv = read(
           pipeline(
               `xtract -pattern Row -element taxon rank`;
               stdin = IOBuffer(sample_xml),
           ),
           String,
       )
"Ursidae\tfamily\nSelachii\tsuperorder\n"

The external program receives sample_xml through standard input. Julia captures the program’s standard output in sample_tsv.

2.6 Save and read text

write stores the captured string and returns the number of bytes written:

julia> sample_path = joinpath(raw_dir, "xtract-example.tsv")
"data/raw/xtract-example.tsv"

julia> write(sample_path, sample_tsv)
35

julia> readlines(sample_path)
2-element Vector{String}:
 "Ursidae\tfamily"
 "Selachii\tsuperorder"

open can direct a program’s standard output to a file without first materializing that output as a String:

julia> open(joinpath(raw_dir, "xtract-example-direct.tsv"), "w") do output
           run(
               pipeline(
                   `xtract -pattern Row -element taxon rank`;
                   stdin = IOBuffer(sample_xml),
                   stdout = output,
               ),
           )
       end;

This form still invokes only 1 external program.

3 Resolve organism concepts with NCBI Taxonomy

Common names do not define exact database targets. A search for bears can include extant species, extinct species, subspecies, environmental samples, and records identified only to genus.

The NCBI Taxonomy Browser shows the accepted name, rank, lineage, and Taxonomy ID for a name. The browser resolves bears to Ursidae, Taxonomy ID 9632, at the rank family.

The following Entrez query selects the specified, non-extinct species beneath Ursidae:

txid9632[subtree] AND species[rank] AND specified[prop] NOT extinct[prop]
Query term Selection
txid9632[subtree] Ursidae and all descendants.
species[rank] Taxa assigned the species rank.
specified[prop] Taxa identified more precisely than Ursus sp. or an environmental sample.
NOT extinct[prop] Taxa without the NCBI extinct property.

NCBI Taxonomy supplies the names and classification used by NCBI sequence records. NCBI states that its taxonomy is not an authoritative nomenclatural source or a phylogenetic hypothesis. The NCBI Taxonomy documentation describes its scope.

3.1 Retrieve the extant bear species

Store the query as a Julia string:

julia> bear_taxonomy_query = "txid9632[subtree] AND species[rank] AND specified[prop] NOT extinct[prop]";

julia> write(
           joinpath(raw_dir, "bear-taxonomy-query.txt"),
           bear_taxonomy_query * "\n",
       );

Run esearch and capture its structured result:

julia> bear_search_xml = read(
           `esearch -db taxonomy -query $bear_taxonomy_query`,
           String,
       );

Feed that result to a single efetch process and capture the returned Taxonomy records:

julia> bear_taxonomy_xml = read(
           pipeline(
               `efetch -format xml`;
               stdin = IOBuffer(bear_search_xml),
           ),
           String,
       );

Feed the records to a single xtract process:

julia> bear_taxonomy_tsv = read(
           pipeline(
               `xtract -pattern Taxon -element TaxId ScientificName Rank`;
               stdin = IOBuffer(bear_taxonomy_xml),
           ),
           String,
       );

Split the captured text into lines and tab-separated fields:

julia> bear_lines = split(chomp(bear_taxonomy_tsv), '\n');

julia> bear_fields = split.(bear_lines, '\t');

julia> first(bear_fields)
3-element Vector{SubString{String}}:
 "9646"
 "Ailuropoda melanoleuca"
 "species"

Construct and sort a DataFrame:

julia> bear_taxa = DataFrame(
           taxid = parse.(Int, getindex.(bear_fields, 1)),
           scientific_name = String.(getindex.(bear_fields, 2)),
           rank = String.(getindex.(bear_fields, 3)),
       );

julia> sort!(bear_taxa, :scientific_name);

julia> nrow(bear_taxa)
8

julia> bear_taxa.scientific_name
8-element Vector{String}:
 "Ailuropoda melanoleuca"
 "Helarctos malayanus"
 "Melursus ursinus"
 "Tremarctos ornatus"
 "Ursus americanus"
 "Ursus arctos"
 "Ursus maritimus"
 "Ursus thibetanus"

NCBI databases change. Investigate a result other than 8 rows before retrieving sequence records.

Serialize the sorted rows and the Taxonomy ID column with Julia:

julia> bear_taxon_lines = [
           join((row.taxid, row.scientific_name, row.rank), '\t')
           for row in eachrow(bear_taxa)
       ];

julia> write(
           joinpath(raw_dir, "bear-taxa.tsv"),
           join(bear_taxon_lines, '\n') * "\n",
       );

julia> bear_taxids = string.(bear_taxa.taxid);

julia> write(
           joinpath(raw_dir, "bear-taxids.txt"),
           join(bear_taxids, '\n') * "\n",
       );

3.2 Retrieve the extant shark families

The common name sharks does not correspond to Chondrichthyes, which also contains chimaeras, or Elasmobranchii, which also contains rays. The current NCBI classification places sharks beneath Selachii. The Taxonomy Browser tree shows these inclusions.

Resolve the exact scientific name:

julia> selachii_name_query = "\"Selachii\"[Scientific Name]";

julia> selachii_search_xml = read(
           `esearch -db taxonomy -query $selachii_name_query`,
           String,
       );

julia> selachii_xml = read(
           pipeline(
               `efetch -format xml`;
               stdin = IOBuffer(selachii_search_xml),
           ),
           String,
       );

julia> selachii_tsv = read(
           pipeline(
               `xtract -pattern Taxon -element TaxId ScientificName Rank`;
               stdin = IOBuffer(selachii_xml),
           ),
           String,
       );

julia> selachii_fields = split(chomp(selachii_tsv), '\t');

julia> @assert length(selachii_fields) == 3

julia> selachii_taxid = parse(Int, selachii_fields[1])

Use the returned Taxonomy ID to form the family query:

julia> shark_family_query = "txid$(selachii_taxid)[subtree] AND family[rank] AND specified[prop] NOT extinct[prop]";

julia> shark_search_xml = read(
           `esearch -db taxonomy -query $shark_family_query`,
           String,
       );

julia> shark_taxonomy_xml = read(
           pipeline(
               `efetch -format xml`;
               stdin = IOBuffer(shark_search_xml),
           ),
           String,
       );

julia> shark_taxonomy_tsv = read(
           pipeline(
               `xtract -pattern Taxon -element TaxId ScientificName Rank`;
               stdin = IOBuffer(shark_taxonomy_xml),
           ),
           String,
       );

Convert the returned fields into columns:

julia> shark_lines = split(chomp(shark_taxonomy_tsv), '\n');

julia> shark_fields = split.(shark_lines, '\t');

julia> shark_families = DataFrame(
           taxid = parse.(Int, getindex.(shark_fields, 1)),
           scientific_name = String.(getindex.(shark_fields, 2)),
           rank = String.(getindex.(shark_fields, 3)),
       );

julia> sort!(shark_families, :scientific_name);

julia> select(shark_families, :scientific_name, :taxid)

Save the query and returned table:

julia> shark_family_lines = [
           join((row.taxid, row.scientific_name, row.rank), '\t')
           for row in eachrow(shark_families)
       ];

julia> write(
           joinpath(raw_dir, "shark-family-query.txt"),
           shark_family_query * "\n",
       );

julia> write(
           joinpath(raw_dir, "shark-families.tsv"),
           join(shark_family_lines, '\n') * "\n",
       );

4 Combine identifiers from multiple queries

Separate searches express a sampling design that names independent targets rather than 1 taxonomic subtree.

4.1 Save separate results and combine them

Specify 1 representative for each of 3 mammal orders:

julia> mammal_targets = DataFrame(
           order = ["Primates", "Rodentia", "Artiodactyla"],
           scientific_name = [
               "Homo sapiens",
               "Mus musculus",
               "Bos taurus",
           ],
           file_stem = ["primates", "rodents", "artiodactyls"],
       );

julia> mammal_queries = [
           "\"$(name)\"[Scientific Name]"
           for name in mammal_targets.scientific_name
       ];

Run each esearch invocation, then pass each captured result to a separate efetch invocation:

julia> mammal_search_results = [
           read(`esearch -db taxonomy -query $query`, String)
           for query in mammal_queries
       ];

julia> mammal_uid_texts = [
           read(
               pipeline(
                   `efetch -format uid`;
                   stdin = IOBuffer(search_xml),
               ),
               String,
           )
           for search_xml in mammal_search_results
       ];

julia> mammal_targets.taxid = parse.(Int, strip.(mammal_uid_texts));

julia> select(mammal_targets, :order, :scientific_name, :taxid)
3×3 DataFrame
 Row │ order          scientific_name  taxid
     │ String         String           Int64
─────┼────────────────────────────────────────
   1 │ Primates       Homo sapiens       9606
   2 │ Rodentia       Mus musculus      10090
   3 │ Artiodactyla   Bos taurus         9913

Write 1 identifier file per query:

julia> mammal_id_paths = [
           joinpath(raw_dir, "$(stem)-taxid.txt")
           for stem in mammal_targets.file_stem
       ];

julia> write.(mammal_id_paths, mammal_uid_texts);

julia> readlines.(mammal_id_paths)
3-element Vector{Vector{String}}:
 ["9606"]
 ["10090"]
 ["9913"]

Read the separate files, concatenate their rows, and write the combined file:

julia> combined_mammal_taxids = reduce(vcat, readlines.(mammal_id_paths))
3-element Vector{String}:
 "9606"
 "10090"
 "9913"

julia> write(
           joinpath(raw_dir, "mammal-representative-taxids.txt"),
           join(combined_mammal_taxids, '\n') * "\n",
       );

4.2 Append repeated query results

Open a fresh destination and append each captured efetch result to its IOStream:

julia> appended_path = joinpath(
           raw_dir,
           "mammal-representative-taxids-appended.txt",
       );

julia> open(appended_path, "w") do output
           for query in mammal_queries
               search_xml = read(
                   `esearch -db taxonomy -query $query`,
                   String,
               )
               uid_text = read(
                   pipeline(
                       `efetch -format uid`;
                       stdin = IOBuffer(search_xml),
                   ),
                   String,
               )
               write(output, uid_text)
           end
       end;

julia> @assert readlines(appended_path) == combined_mammal_taxids

Opening the destination with "w" replaces any previous content before the loop begins. Opening the file separately with "a" would retain old content and duplicate identifiers when the cell is rerun.

5 Query nucleotide-record availability

The nuccore database contains nucleotide records from GenBank, RefSeq, and other NCBI sources. Taxonomic coverage does not imply marker coverage.

The query

txid29073[ORGN:noexp] AND CYTB[GENE]

selects records indexed directly to Ursus maritimus that contain CYTB in the gene field. ORGN:noexp prevents the organism term from expanding to descendant taxa. The EDirect search documentation lists sequence-database fields and filters.

5.1 Save accessions from 1 query

Search for mitochondrial giant-panda CYTB records between 1,000 and 1,200 nucleotides:

julia> panda_cytb_query = "txid9646[ORGN:noexp] AND CYTB[GENE] AND mitochondrion[FILT] AND 1000:1200[SLEN]";

julia> panda_search_xml = read(
           `esearch -db nuccore -query $panda_cytb_query`,
           String,
       );

julia> panda_count_text = read(
           pipeline(
               `xtract -pattern ENTREZ_DIRECT -element Count`;
               stdin = IOBuffer(panda_search_xml),
           ),
           String,
       );

julia> panda_record_count = parse(Int, strip(panda_count_text))

julia> panda_accession_text = read(
           pipeline(
               `efetch -format acc`;
               stdin = IOBuffer(panda_search_xml),
           ),
           String,
       );

julia> panda_candidate_accessions = split(
           chomp(panda_accession_text),
           '\n',
       );

julia> write(
           joinpath(raw_dir, "giant-panda-CYTB-candidate-accessions.txt"),
           panda_accession_text,
       );

The first returned accession is not automatically the preferred record. Record source, sequence length, definition, annotations, and specimen metadata affect record selection.

5.2 Count records for each taxon and marker

Compare the mitochondrial markers CYTB and COX1 with the nuclear marker RAG1:

julia> markers = ["CYTB", "COX1", "RAG1"];

julia> marker_rows = vec([
           let
               count_query = "txid$(taxon.taxid)[ORGN:noexp] AND $(marker)[GENE]"
               search_xml = read(
                   `esearch -db nuccore -query $count_query`,
                   String,
               )
               count_text = read(
                   pipeline(
                       `xtract -pattern ENTREZ_DIRECT -element Count`;
                       stdin = IOBuffer(search_xml),
                   ),
                   String,
               )
               sleep(0.4)
               (
                   taxid = taxon.taxid,
                   taxon = taxon.scientific_name,
                   marker = marker,
                   record_count = parse(Int, strip(count_text)),
               )
           end
           for taxon in eachrow(bear_taxa), marker in markers
       ]);

julia> marker_counts = DataFrame(marker_rows);

julia> sort!(marker_counts, [:taxon, :marker]);

julia> marker_counts

The comprehension issues 24 sequential esearch requests. NCBI’s E-utilities usage guidelines limit unauthenticated requests to 3 per second and recommend batching large retrievals. The sleep call keeps this loop below that limit.

Serialize the long table:

julia> marker_count_lines = [
           join(
               (
                   row.taxid,
                   row.taxon,
                   row.marker,
                   row.record_count,
               ),
               '\t',
           )
           for row in eachrow(marker_counts)
       ];

julia> marker_count_text = join(
           vcat(
               ["taxid\ttaxon\tmarker\trecord_count"],
               marker_count_lines,
           ),
           '\n',
       ) * "\n";

julia> write(
           joinpath(raw_dir, "bear-marker-counts-long.tsv"),
           marker_count_text,
       );

Reshape the long table into a taxon-by-marker matrix:

julia> marker_matrix = unstack(
           marker_counts,
           :taxon,
           :marker,
           :record_count,
       );

julia> sort!(marker_matrix, :taxon);

julia> marker_matrix

A record count measures availability, not orthology, completeness, correct identification, sequence quality, or independence among records. A count of 0 can also reflect a gene-name synonym or missing annotation.

6 Inspect candidate records

Search for complete RefSeq mitochondrial genomes within Ursidae:

julia> bear_mitogenome_query = "txid9632[ORGN] AND mitochondrion[FILT] AND refseq[FILT] AND \"complete genome\"[TITLE]";

julia> mitogenome_search_xml = read(
           `esearch -db nuccore -query $bear_mitogenome_query`,
           String,
       );

julia> mitogenome_count_text = read(
           pipeline(
               `xtract -pattern ENTREZ_DIRECT -element Count`;
               stdin = IOBuffer(mitogenome_search_xml),
           ),
           String,
       );

julia> mitogenome_record_count = parse(Int, strip(mitogenome_count_text))

Fetch document summaries and extract 4 fields:

julia> mitogenome_docsum_xml = read(
           pipeline(
               `efetch -format docsum`;
               stdin = IOBuffer(mitogenome_search_xml),
           ),
           String,
       );

julia> mitogenome_candidate_tsv = read(
           pipeline(
               `xtract -pattern DocumentSummary -element AccessionVersion TaxId Slen Title`;
               stdin = IOBuffer(mitogenome_docsum_xml),
           ),
           String,
       );

julia> candidate_lines = split(
           chomp(mitogenome_candidate_tsv),
           '\n',
       );

julia> candidate_lines = candidate_lines[.!isempty.(candidate_lines)];

julia> candidate_fields = split.(candidate_lines, '\t');

julia> mitogenome_candidates = DataFrame(
           accession = String.(getindex.(candidate_fields, 1)),
           taxid = parse.(Int, getindex.(candidate_fields, 2)),
           sequence_length = parse.(Int, getindex.(candidate_fields, 3)),
           title = String.(getindex.(candidate_fields, 4)),
       );

julia> sort!(mitogenome_candidates, [:taxid, :accession]);

julia> mitogenome_candidates

Save the candidate table and query:

julia> candidate_table_lines = [
           join(
               (
                   row.accession,
                   row.taxid,
                   row.sequence_length,
                   row.title,
               ),
               '\t',
           )
           for row in eachrow(mitogenome_candidates)
       ];

julia> write(
           joinpath(raw_dir, "bear-mitogenome-candidates.tsv"),
           join(candidate_table_lines, '\n') * "\n",
       );

julia> write(
           joinpath(raw_dir, "bear-mitogenome-query.txt"),
           bear_mitogenome_query * "\n",
       );

Compare accession version, Taxonomy ID, sequence length, title, record source, and feature annotations. The following set contains 1 complete mitochondrial RefSeq record for each target species:

julia> selected_records = DataFrame(
           species = [
               "Ailuropoda melanoleuca",
               "Helarctos malayanus",
               "Melursus ursinus",
               "Tremarctos ornatus",
               "Ursus americanus",
               "Ursus arctos",
               "Ursus maritimus",
               "Ursus thibetanus",
           ],
           accession = [
               "NC_009492.1",
               "NC_009968.1",
               "NC_009970.1",
               "NC_009969.1",
               "NC_003426.1",
               "NC_003427.1",
               "NC_003428.1",
               "NC_009971.1",
           ],
       )

The common record type reduces differences caused by record scope and annotation practice. The .1 suffix identifies the exact record version.

7 Save the selected accession manifest

Construct 1 Entrez query from the selected accession column:

julia> accession_terms = [
           "$(accession)[ACCN]"
           for accession in selected_records.accession
       ];

julia> selected_accession_query = "(" * join(

11 Interpret the data

bears-CYTB-raw.fasta contains 1 CYTB sequence for each of the 8 specified, non-extinct bear species returned by the Taxonomy query.

  • CYTB is 1 linked mitochondrial locus.
  • A mitochondrial gene tree can differ from the species history because of introgression, lineage sorting, sampling, and other processes.
  • One record per species does not represent within-species variation.
  • Database annotations and taxonomic assignments can change.
  • The raw FASTA sequences require alignment and alignment inspection before phylogenetic inference.
