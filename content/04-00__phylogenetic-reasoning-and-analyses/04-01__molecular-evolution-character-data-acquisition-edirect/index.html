Acquiring molecular characters with EDirect from Julia

Author

Jeet Sukumaran

NCBI Entrez Direct (EDirect) searches and retrieves records from NCBI’s Entrez databases. Julia can run EDirect programs from the REPL and keep the returned records as text or save them to files.

1 Preparation

1.1 Installing EDirect

Run the official EDirect installer from a system shell:

$ sh -c "$(curl -fsSL https://ftp.ncbi.nlm.nih.gov/entrez/entrezdirect/install-edirect.sh)"

Accept the installer’s offer to add EDirect to PATH. Open a new terminal, then confirm that the required programs are available:

$ command -v esearch efetch epost xtract
/home/student/edirect/esearch
/home/student/edirect/efetch
/home/student/edirect/epost
/home/student/edirect/xtract

$ esearch -version
26.2

The paths contain the local user name. The installed version may be newer than the version shown here.

NoteInstallation details

EDirect runs on Unix and macOS. On Windows, run EDirect and Julia in a Unix-compatible environment such as Windows Subsystem for Linux (WSL).

The EDirect manual contains the current installer command. The release notes record changes to EDirect programs and output.

The $ character in the examples marks a shell prompt. It is not part of the command.

1.2 Starting a working directory

Create a project directory with a directory for raw downloads, then make the project directory current:

$ mkdir -p /home/student/projects/learning/scientific-julia/bear-edirect-project/data/raw
$ cd /home/student/projects/learning/scientific-julia/bear-edirect-project

2 Basic workflow

2.1 Basic workflow for a single record

The accession NC_009492.1 identifies a complete mitochondrial genome for the giant panda, Ailuropoda melanoleuca.

Workflow alternate: Basic workflow for a single record from the shell

Pass the accession directly to efetch and save the returned FASTA record:

$ efetch -db nuccore -id NC_009492.1 -format fasta \
    > data/raw/NC_009492.1.shell.fasta

-db nuccore selects the NCBI Nucleotide database. -id NC_009492.1 identifies the record, and -format fasta requests FASTA output. The backslash continues the command on the next line. The shell’s > operator writes the standard output to the path on its right.

Inspect the first line of the saved record:

$ head -n 1 data/raw/NC_009492.1.shell.fasta
>NC_009492.1 Ailuropoda melanoleuca mitochondrion, complete genome

The Julia REPL can construct and run the same EDirect command. Start Julia from the project directory:

$ julia --project=.

Represent the raw-data directory and accession as Julia strings:

julia> raw_dir = joinpath("data", "raw")
"data/raw"

julia> accession = "NC_009492.1"
"NC_009492.1"

Interpolate the accession into the command and capture the returned text:

julia> fasta_record = read(
           `efetch -db nuccore -id $accession -format fasta`,
           String,
       );

The first argument to read is the EDirect command. The second argument, String, specifies that read must return the command’s standard output as a Julia string.

Inspect the FASTA header:

julia> first(split(fasta_record, '\n'))
">NC_009492.1 Ailuropoda melanoleuca mitochondrion, complete genome"

Save the returned text:

julia> fasta_path = joinpath(raw_dir, "NC_009492.1.julia.fasta")
"data/raw/NC_009492.1.julia.fasta"

julia> write(fasta_path, fasta_record);

julia> isfile(fasta_path)
true

write receives the destination path first and the captured FASTA text second.

NoteExternal commands in Julia

Backticks construct a Julia Cmd value. They do not run the command by themselves. A Cmd value is a template for a command that will be executed in the shell by functions such as run, read, or pipeline when passed as the first argument, with $-prefixed constructs replaced by the Julia value.

Here, $accession will be replaced with its string value when the argument is added to the efetch command in the shell.

read(command, String) runs the command and captures its standard output as a Julia string. See Julia’s external-program documentation for the complete command interface.

TipAccession versions

The .1 suffix identifies the exact version of the record. Retaining the version suffix makes the selected database record explicit.

2.2 Basic workflow for multiple records

EDirect accepts multiple accession versions as one comma-separated -id argument. The following three accessions identify complete mitochondrial genomes for a giant panda, a brown bear, and a polar bear.

Workflow alternate: Basic workflow for multiple records from the shell

Supply the comma-separated accessions directly to efetch:

$ efetch \
    -db nuccore \
    -id NC_009492.1,NC_003427.1,NC_003428.1 \
    -format fasta \
    > data/raw/three-bear-mitogenomes.shell.fasta

A backslash at the end of a shell line continues the command on the next line. The output file contains the three FASTA records in one stream.

Count the FASTA headers to confirm the number of records:

$ grep -c '^>' data/raw/three-bear-mitogenomes.shell.fasta
3

Represent the same accession versions as a Julia collection:

julia> example_accessions = [
           "NC_009492.1",
           "NC_003427.1",
           "NC_003428.1",
       ]
3-element Vector{String}:
 "NC_009492.1"
 "NC_003427.1"
 "NC_003428.1"

Join the strings into the comma-separated argument accepted by efetch:

julia> example_accession_argument = join(example_accessions, ",")
"NC_009492.1,NC_003427.1,NC_003428.1"

join returns one string and leaves example_accessions unchanged. The collection remains available for inspection or later reuse.

Interpolate the joined string into the command and capture all three records:

julia> example_fasta = read(
           `efetch -db nuccore -id $example_accession_argument -format fasta`,
           String,
       );

julia> count('>', example_fasta)
3

The read call again receives a command and the requested return type. Julia passes the interpolated accession string to efetch as one command argument.

Save the combined FASTA text:

julia> example_fasta_path = joinpath(
           raw_dir,
           "three-bear-mitogenomes.julia.fasta",
       )
"data/raw/three-bear-mitogenomes.julia.fasta"

julia> write(example_fasta_path, example_fasta);

julia> isfile(example_fasta_path)
true

2.3 Searching when the accession is unknown

An Entrez query can combine an organism, a gene, a genomic location, and a sequence-length range. This query finds mitochondrial CYTB records from Ailuropoda melanoleuca with lengths from 1,000 through 1,200 nucleotides:

julia> panda_cytb_query = "txid9646[ORGN:noexp] AND CYTB[GENE] AND mitochondrion[FILT] AND 1000:1200[SLEN]";

esearch finds the matching records. efetch returns their accession numbers:

julia> candidate_accessions = read(
           pipeline(
               `esearch -db nuccore -query $panda_cytb_query`,
               `efetch -format acc`,
           ),
           String,
       );

julia> print(candidate_accessions)
AY390359.1
AY390360.1
KP306772.1
KP306773.1

NCBI database contents change. A later search may return a different set or order.

NoteQuery terms

txid9646[ORGN:noexp] restricts the organism to NCBI Taxonomy ID 9646 without expanding the search to descendant taxa.

CYTB[GENE] searches the gene field. mitochondrion[FILT] restricts the location, and 1000:1200[SLEN] restricts sequence length.

The EDirect search documentation lists the available fields and filters.

NoteCommand pipelines

pipeline(search_command, fetch_command) connects the output of esearch to the input of efetch. read(..., String) captures the output of the final program.

The structured message between EDirect programs includes the active database and the matching record set. The later command therefore does not repeat the database name or record identifiers.

Inspect the accession, length, and title of each candidate before selecting a record:

julia> candidate_table = read(
           pipeline(
               `esearch -db nuccore -query $panda_cytb_query`,
               `efetch -format docsum`,
               `xtract -pattern DocumentSummary -element AccessionVersion Slen Title`,
           ),
           String,
       );

julia> print(candidate_table)
AY390359.1  1140  Ailuropoda melanoleuca from Daili cytochrome b (cytb) gene, complete cds; mitochondrial
AY390360.1  1140  Ailuropoda melanoleuca from Xiaoxiao cytochrome b (cytb) gene, complete cds; mitochondrial
KP306772.1  1140  Ailuropoda melanoleuca voucher JDS 05001 cytochrome b (cytb) gene, complete cds; mitochondrial
KP306773.1  1140  Ailuropoda melanoleuca voucher JDS 97001 cytochrome b (cytb) gene, complete cds; mitochondrial

The displayed columns are tab-separated. Save the candidate table with a .tsv extension:

julia> candidate_path = joinpath(raw_dir, "giant-panda-CYTB-candidates.tsv")
"data/raw/giant-panda-CYTB-candidates.tsv"

julia> write(candidate_path, candidate_table);
WarningRecord selection

The first search result is not automatically the preferred record. Compare the record source, sequence length, definition, feature annotations, specimen or voucher information, and publication before selecting a sequence.

2.4 Defining the terminal taxa

NCBI Taxonomy ID 9632 identifies Ursidae. The following query selects taxa beneath Ursidae that have species rank, are specified, and do not have NCBI’s extinct property:

julia> bear_taxonomy_query = "txid9632[subtree] AND species[rank] AND specified[prop] NOT extinct[prop]";

Retrieve each matching Taxonomy ID, scientific name, and rank:

julia> bear_taxonomy_tsv = read(
           pipeline(
               `esearch -db taxonomy -query $bear_taxonomy_query`,
               `efetch -format xml`,
               `xtract -pattern Taxon -element TaxId ScientificName Rank`,
           ),
           String,
       );

julia> print(bear_taxonomy_tsv)
9634    Helarctos malayanus     species
9636    Melursus ursinus        species
9638    Tremarctos ornatus      species
9642    Ursus thibetanus        species
9643    Ursus americanus        species
9644    Ursus arctos            species
9646    Ailuropoda melanoleuca  species
29073   Ursus maritimus         species

Save the query and its result:

julia> write(
           joinpath(raw_dir, "bear-taxonomy-query.txt"),
           bear_taxonomy_query * "\n",
       );

julia> write(
           joinpath(raw_dir, "bear-taxa.tsv"),
           bear_taxonomy_tsv,
       );
NoteScope of NCBI Taxonomy

NCBI Taxonomy supplies the organism names and classification attached to NCBI sequence records. It is not a primary authority for taxonomic or phylogenetic conclusions.

The NCBI Taxonomy Browser shows the record for Ursidae. The NCBI Taxonomy documentation describes the database and Taxonomy IDs.

3.2 Retrieving identifiers from separate searches

Separate searches can represent taxa that do not form 1 taxonomic subtree. The following queries select 1 named species from each of 3 mammal orders:

julia> human_query = "\"Homo sapiens\"[Scientific Name]";

julia> mouse_query = "\"Mus musculus\"[Scientific Name]";

julia> cattle_query = "\"Bos taurus\"[Scientific Name]";

Run each Taxonomy search and capture its Taxonomy ID:

julia> human_taxid = readchomp(
           pipeline(
               `esearch -db taxonomy -query $human_query`,
               `efetch -format uid`,
           ),
       )
"9606"

julia> mouse_taxid = readchomp(
           pipeline(
               `esearch -db taxonomy -query $mouse_query`,
               `efetch -format uid`,
           ),
       )
"10090"

julia> cattle_taxid = readchomp(
           pipeline(
               `esearch -db taxonomy -query $cattle_query`,
               `efetch -format uid`,
           ),
       )
"9913"

Collect the identifiers in the same order as the queries:

julia> mammal_taxids = [human_taxid, mouse_taxid, cattle_taxid]
3-element Vector{String}:
 "9606"
 "10090"
 "9913"

Save the combined identifiers:

julia> mammal_taxid_path = joinpath(
           raw_dir,
           "mammal-representative-taxids.txt",
       )
"data/raw/mammal-representative-taxids.txt"

julia> write(
           mammal_taxid_path,
           join(mammal_taxids, '\n') * "\n",
       );

4 Advanced workflows

4.1 Applying 1 search to a collection of queries

Each separate mammal search applies the same operation to a different query. Store the query strings in a collection:

julia> mammal_queries = [human_query, mouse_query, cattle_query];

map applies the anonymous function query -> ... to each query string and collects the returned Taxonomy IDs:

julia> mapped_mammal_taxids = map(
           query -> readchomp(
               pipeline(
                   `esearch -db taxonomy -query $query`,
                   `efetch -format uid`,
               ),
           ),
           mammal_queries,
       )
3-element Vector{String}:
 "9606"
 "10090"
 "9913"

julia> mapped_mammal_taxids == mammal_taxids
true

The returned identifiers have the same order as the corresponding query strings.

4.2 Creating a taxon-by-marker availability matrix

A record-count matrix identifies gaps in database coverage before records are reviewed. It does not establish orthology, completeness, correct identification, sequence quality, or independence among records.

NoteDataFrames package

This workflow uses DataFrames.jl to organize and reshape the query results. Add it from Julia’s package mode:

julia> ]

pkg> add DataFrames

Press Backspace at an empty pkg> prompt to return to julia>.

Load the required DataFrames.jl names:

julia> using DataFrames: DataFrame, leftjoin, nrow, select, unstack

Convert the saved Taxonomy result into a table:

julia> taxonomy_lines = split(chomp(bear_taxonomy_tsv), '\n');

julia> taxonomy_fields = split.(taxonomy_lines, '\t');

julia> bear_taxa = DataFrame(
           taxid = parse.(Int, getindex.(taxonomy_fields, 1)),
           species = String.(getindex.(taxonomy_fields, 2)),
       );

julia> sort!(bear_taxa, :species);

julia> nrow(bear_taxa)
8

Create an empty result table and specify the markers:

julia> marker_counts = DataFrame(
           taxid = Int[],
           species = String[],
           marker = String[],
           record_count = Int[],
       );

julia> markers = ["CYTB", "COX1", "RAG1"];

Issue 1 search for each taxon-marker combination and append the returned count:

julia> for taxon in eachrow(bear_taxa)
           for marker in markers
               query = "txid$(taxon.taxid)[ORGN:noexp] AND $(marker)[GENE]"
               count_text = read(
                   pipeline(
                       `esearch -db nuccore -query $query`,
                       `xtract -pattern ENTREZ_DIRECT -element Count`,
                   ),
                   String,
               )
               push!(
                   marker_counts,
                   (
                       taxid = taxon.taxid,
                       species = taxon.species,
                       marker = marker,
                       record_count = parse(Int, strip(count_text)),
                   ),
               )
           end
       end

Reshape the long result into 1 row per species and 1 column per marker:

julia> marker_matrix = unstack(
           marker_counts,
           :species,
           :marker,
           :record_count,
       );

julia> sort!(marker_matrix, :species)
WarningNCBI request limits

Keep repeated searches sequential. Do not wrap the request loop in parallel execution.

NCBI permits up to 3 E-utility requests per second without an API key and up to 10 per second by default with a key. NCBI recommends Entrez History for large batches. EDirect coordinates requests and retries for its sequential pipelines. See the E-utilities usage guidelines.

4.3 Posting an accession collection

For larger identifier collections, epost places the identifiers on the Entrez History server. Construct the newline-separated input:

julia> accession_input = join(accessions, '\n') * "\n";

Supply the string to epost through standard input and capture the returned history message:

julia> posted_accessions = read(
           pipeline(
               `epost -db nuccore`;
               stdin = IOBuffer(accession_input),
           ),
           String,
       );

Feed that message to efetch:

julia> posted_fasta = read(
           pipeline(
               `efetch -format fasta`;
               stdin = IOBuffer(posted_accessions),
           ),
           String,
       );

julia> count('>', posted_fasta)
8
NoteStandard input

IOBuffer(accession_input) exposes a Julia string as an input stream. The stdin keyword attaches that stream to epost.

The same pattern supplies the structured history message to efetch without writing an intermediate file.

4.4 Extracting annotated CYTB sequences

Retrieve the reviewed records as INSDSeq XML, which exposes the annotated features to xtract:

julia> insdseq_xml = read(
           pipeline(
               `efetch -format gbc`;
               stdin = IOBuffer(posted_accessions),
           ),
           String,
       );

Extract the accession, gene qualifier, and nucleotide sequence beneath every annotated coding-sequence feature:

julia> coding_sequence_tsv = read(
           pipeline(
               `xtract -insd CDS gene sub_sequence`;
               stdin = IOBuffer(insdseq_xml),
           ),
           String,
       );

The official EDirect nucleotide examples document the CDS gene sub_sequence extraction form.

Convert the tab-separated result to a DataFrame:

julia> coding_sequence_lines = split(chomp(coding_sequence_tsv), '\n');

julia> coding_sequence_fields = split.(coding_sequence_lines, '\t');

julia> coding_sequences = DataFrame(
           accession = String.(getindex.(coding_sequence_fields, 1)),
           gene = String.(getindex.(coding_sequence_fields, 2)),
           sequence = uppercase.(String.(getindex.(coding_sequence_fields, 3))),
       );

Select CYTB, attach the species names, and inspect sequence lengths:

julia> cytb = coding_sequences[
           uppercase.(coding_sequences.gene) .== "CYTB",
           :,
       ];

julia> selected_records = DataFrame(
           species = species_names,
           accession = accessions,
       );

julia> cytb = leftjoin(cytb, selected_records; on = :accession);

julia> sort!(cytb, :species);

julia> cytb.sequence_length = length.(cytb.sequence);

julia> select(cytb, :species, :accession, :gene, :sequence_length)

Confirm that each reviewed species has 1 complete CYTB coding sequence:

julia> @assert nrow(cytb) == length(species_names) == 8

julia> @assert length(unique(cytb.species)) == 8

julia> @assert all(cytb.sequence_length .== 1140)

Construct taxon-labelled FASTA records and save them:

julia> fasta_ids = replace.(cytb.species, ' ' => '_') .* "|" .* cytb.accession .* "|CYTB";

julia> cytb_fasta_records = [
           ">$(fasta_ids[index])\n$(cytb.sequence[index])"
           for index in eachindex(fasta_ids)
       ];

julia> cytb_fasta = join(cytb_fasta_records, '\n') * "\n";

julia> cytb_fasta_path = joinpath(raw_dir, "bears-CYTB-raw.fasta")
"data/raw/bears-CYTB-raw.fasta"

julia> write(cytb_fasta_path, cytb_fasta);

julia> fasta_ids

  2. Retrieve the record in FASTA and GenBank formats.
  3. Save both records under filenames containing the accession version.
  4. Compare the source and feature annotations with KP306772.1.

Change the taxonomic scope

  1. Select another NCBI Taxonomy ID.
  2. Retrieve its specified, non-extinct species.
  3. Save the exact query and returned Taxonomy table.
  4. Inspect unexpected or missing taxa before continuing.
Exercise 3

Compare marker availability
