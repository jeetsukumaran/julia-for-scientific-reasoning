Curating and aligning molecular character data

Author

Jeet Sukumaran

Sequence records become an analysis-ready character matrix only after their identities, contents, labels, and homology have been examined. This workflow uses SeqKit to inspect a collection of bear CYTB coding sequences, constructs informative sequence labels, and uses MAFFT to construct a multiple sequence alignment.

The checks below can expose incomplete records, unexpected characters, identifier mismatches, and disrupted reading frames. They do not by themselves establish orthology, correct taxonomic identification, or an appropriate alignment.

A multiple sequence alignment is a hypothesis of positional homology, not a neutral change of file format.

1 Preparation

1.1 Installing SeqKit and MAFFT

SeqKit inspects and transforms FASTA and FASTQ records. MAFFT constructs multiple alignments of nucleotide or amino-acid sequences.

Install each program from its project website:

  • Download SeqKit
  • Download and install MAFFT

Confirm that both executables are available:

Shell
$ seqkit version
$ mafft --version

The reported versions may be newer than those used to prepare this tutorial.

TipOptional installation with Conda

Conda or Mamba can install both programs from Bioconda:

Shell
$ conda install -c bioconda seqkit mafft

1.2 Acquiring the example data

This tutorial begins with the CYTB records produced in the EDirect data-acquisition tutorial:

Download the bear CYTB sequences

Create the project directory and save the FASTA file under data/raw:

Shell
$ mkdir -p /home/student/projects/learning/scientific-julia/bear-cytb-curation/data/raw
$ cd /home/student/projects/learning/scientific-julia/bear-cytb-curation
$ julia --project=.
NoteRequired Julia packages

This tutorial uses CSV.jl to read tab-separated program output and DataFrames.jl to organize those data. Install them in the active project if necessary:

REPL
julia> import Pkg

julia> Pkg.add(["CSV", "DataFrames"])

Load the packages:

REPL
julia> import CSV

julia> using DataFrames: DataFrame, nrow, select

Set the project paths and create separate directories for curated records, alignments, and reports:

REPL
julia> project_dir = "/home/student/projects/learning/scientific-julia/bear-cytb-curation";

julia> raw_dir = joinpath(project_dir, "data", "raw");

julia> curated_dir = joinpath(project_dir, "data", "curated");

julia> aligned_dir = joinpath(project_dir, "data", "aligned");

julia> results_dir = joinpath(project_dir, "results");

julia> mkpath(curated_dir);

julia> mkpath(aligned_dir);

julia> mkpath(results_dir);

Set and verify the input path:

REPL
julia> raw_fasta_path = joinpath(raw_dir, "bears-CYTB.fasta");

julia> isfile(raw_fasta_path)
true

2 Basic workflow

2.1 Auditing the sequence collection

The study design calls for one CYTB record from each of the eight living bear species. Audit the collection against that expected size.

Shell commands

The direct shell command for this is:

Shell
$ seqkit stats --tabular --basename data/raw/bears-CYTB.fasta
file    format  type    num_seqs    sum_len min_len avg_len max_len
bears-CYTB.fasta    FASTA   DNA 8   9120    1140    1140.0  1140

Record the expected collection size in Julia:

REPL
julia> expected_record_count = 8
8

Use seqkit stats to inspect the FASTA collection. --tabular produces a header and one tab-separated result row. --basename reports only the input filename rather than its complete path. Pass the command directly to CSV.read:

REPL
julia> collection_statistics = CSV.read(
           `seqkit stats --tabular --basename $raw_fasta_path`,
           DataFrame;
           delim = '\t',
           stringtype = String,
       );

julia> select(
           collection_statistics,
           :file,
           :type,
           :num_seqs,
           :min_len,
           :max_len,
       )
1×5 DataFrame
 Row │ file              type    num_seqs  min_len  max_len
     │ String            String  Int64     Int64    Int64
─────┼──────────────────────────────────────────────────────
   1 │ bears-CYTB.fasta  DNA            8     1140     1140

Confirm that the FASTA file contains the expected number of records and that the shortest and longest records have the expected length:

REPL
julia> @assert only(collection_statistics.num_seqs) == expected_record_count

julia> @assert only(collection_statistics.min_len) == only(collection_statistics.max_len) == 1140

An assertion produces no output when its condition is true. A false condition stops the workflow with an AssertionError at the failed check.

2.2 Composing the accession-to-species mapping

The raw FASTA file retains accession versions as record identifiers. Compose the taxonomic assignments established while reviewing the source records:

REPL
julia> species_by_accession = Dict(
           "NC_009492.1" => "Ailuropoda melanoleuca",
           "NC_009968.1" => "Helarctos malayanus",
           "NC_009970.1" => "Melursus ursinus",
           "NC_009969.1" => "Tremarctos ornatus",
           "NC_003426.1" => "Ursus americanus",
           "NC_003427.1" => "Ursus arctos",
           "NC_003428.1" => "Ursus maritimus",
           "NC_009971.1" => "Ursus thibetanus",
       );

julia> length(species_by_accession)
8

Each dictionary key is an accession version from the downloaded records. Its value is the corresponding scientific name. These assignments were reviewed during data acquisition. A larger study commonly records the same assignments in its sample metadata.

2.3 Reconciling accession identifiers

The FASTA identifiers should correspond exactly to the composed mapping. seqkit seq --name returns record names without sequences; --only-id reduces each name to its first identifier field. Capture the result and split it into one identifier per Julia string:

REPL
julia> record_identifiers = split(
           chomp(
               read(
                   `seqkit seq --name --only-id $raw_fasta_path`,
                   String,
               ),
           ),
           '\n',
       )
8-element Vector{SubString{String}}:
 "NC_009492.1"
 "NC_009968.1"
 "NC_009970.1"
 "NC_009969.1"
 "NC_003426.1"
 "NC_003427.1"
 "NC_003428.1"
 "NC_009971.1"

Compare the observed FASTA identifiers and expected mapping keys in both directions:

REPL
julia> expected_accessions = collect(keys(species_by_accession));

julia> missing_from_fasta = setdiff(
           expected_accessions,
           record_identifiers,
       )
String[]

julia> missing_from_mapping = setdiff(
           record_identifiers,
           expected_accessions,
       )
SubString{String}[]

julia> allunique(record_identifiers)
true

Retain the explicit checks in the workflow:

REPL
julia> @assert isempty(missing_from_fasta)

julia> @assert isempty(missing_from_mapping)

julia> @assert allunique(record_identifiers)

julia> @assert length(species_by_accession) == expected_record_count

2.4 Inspecting individual records

Convert the FASTA records to tab-separated rows with seqkit fx2tab. --only-id retains the accession rather than the complete FASTA header, --no-qual omits the FASTQ-quality column, --length adds sequence length, and --alphabet reports the nucleotide characters observed in each record.

Shell commands

The direct shell command for this is:

Shell
$ seqkit fx2tab \
    --name \
    --only-id \
    --length \
    --alphabet \
    data/raw/bears-CYTB.fasta
NC_009492.1 1140    ACGT
NC_009968.1 1140    ACGT
NC_009970.1 1140    ACGT
NC_009969.1 1140    ACGT
NC_003426.1 1140    ACGT
NC_003427.1 1140    ACGT
NC_003428.1 1140    ACGT
NC_009971.1 1140    ACGT

Read the same rows into Julia:

REPL
julia> sequence_table = CSV.read(
           `seqkit fx2tab --only-id --no-qual --length --alphabet $raw_fasta_path`,
           DataFrame;
           delim = '\t',
           header = [:accession, :sequence, :length, :alphabet],
           stringtype = String,
       );

julia> select(sequence_table, :accession, :length, :alphabet)
8×3 DataFrame
 Row │ accession    length  alphabet
     │ String       Int64   String
─────┼───────────────────────────────
   1 │ NC_009492.1    1140  ACGT
   2 │ NC_009968.1    1140  ACGT
   3 │ NC_009970.1    1140  ACGT
   4 │ NC_009969.1    1140  ACGT
   5 │ NC_003426.1    1140  ACGT
   6 │ NC_003427.1    1140  ACGT
   7 │ NC_003428.1    1140  ACGT
   8 │ NC_009971.1    1140  ACGT

Confirm that every record has the expected length, contains only unambiguous DNA characters, and has a length divisible by three:

REPL
julia> all(sequence_table.length .== 1140)
true

julia> all(character -> character in "ACGT", join(sequence_table.alphabet))
true

julia> all(sequence_table.length .% 3 .== 0)
true

The final test is necessary for an intact coding sequence, but it does not show that the annotated frame translates correctly.

2.5 Checking the reading frame

Bear mitochondrial CYTB uses the vertebrate mitochondrial genetic code, NCBI translation table 2. Translate each sequence with seqkit translate --transl-table 2, then use seqkit fx2tab to return one identifier and protein sequence per row.

Shell commands

The direct shell commands for this are:

Shell
$ seqkit translate \
    --transl-table 2 \
    data/raw/bears-CYTB.fasta \
    > data/curated/bears-CYTB-translated.fasta

$ seqkit fx2tab \
    --name \
    --only-id \
    --length \
    --alphabet \
    data/curated/bears-CYTB-translated.fasta

Construct the equivalent pipeline in Julia:

REPL
julia> translation_pipeline = pipeline(
           `seqkit translate --transl-table 2 $raw_fasta_path`,
           `seqkit fx2tab --only-id --no-qual`,
       );

julia> translation_tsv = read(translation_pipeline, String);

julia> translations = CSV.read(
           IOBuffer(translation_tsv),
           DataFrame;
           delim = '\t',
           header = [:accession, :protein],
           stringtype = String,
       );

Each translation should end with one terminal stop. Remove that final character when counting amino acids and when searching for internal stops:

REPL
julia> translations.terminal_stop = endswith.(translations.protein, "*");

julia> translations.amino_acids = length.(chop.(translations.protein));

julia> translations.internal_stop = occursin.("*", chop.(translations.protein));

julia> select(
           translations,
           :accession,
           :amino_acids,
           :terminal_stop,
           :internal_stop,
       )
8×4 DataFrame
 Row │ accession    amino_acids  terminal_stop  internal_stop
     │ String       Int64        Bool           Bool
─────┼────────────────────────────────────────────────────────
   1 │ NC_009492.1          379           true          false
   2 │ NC_009968.1          379           true          false
   3 │ NC_009970.1          379           true          false
   4 │ NC_009969.1          379           true          false
   5 │ NC_003426.1          379           true          false
   6 │ NC_003427.1          379           true          false
   7 │ NC_003428.1          379           true          false
   8 │ NC_009971.1          379           true          false

Require the expected protein length, terminal stop, and absence of internal stops:

REPL
julia> @assert all(translations.amino_acids .== 379)

julia> @assert all(translations.terminal_stop)

julia> @assert all(!, translations.internal_stop)
WarningInterpreting translation checks

An internal stop can indicate an incorrect genetic code, wrong orientation or reading frame, a sequencing or annotation error, or a genuine pseudogene. Do not discard the record until the biological and record-level evidence has been examined.

2.6 Constructing informative sequence identifiers

Accession versions provide stable links to database records, while species names make an alignment and inferred phylogeny easier to interpret. Construct one identifier containing the species, accession version, and gene. Underscores replace the space within each scientific name:

REPL
julia> label_by_accession = Dict(
           accession => "$(replace(species, ' ' => '_'))|$(accession)|CYTB"
           for (accession, species) in species_by_accession
       );

julia> label_by_accession["NC_003428.1"]
"Ursus_maritimus|NC_003428.1|CYTB"

Confirm that the identifiers are unique and contain no whitespace or Newick punctuation:

REPL
julia> sequence_labels = collect(values(label_by_accession));

julia> allunique(sequence_labels)
true

julia> all(
           label -> !occursin(r"[\s(),:;]", label),
           sequence_labels,
       )
true

Replace the identifier field in each tab-separated sequence row. The nucleotide sequence remains unchanged:

REPL
julia> curated_rows = [
           "$(label_by_accession[row.accession])\t$(row.sequence)"
           for row in eachrow(sequence_table)
       ];

julia> curated_tsv = join(curated_rows, '\n') * "\n";

Pass the transformed rows to seqkit tab2fx, which converts the first two TSV fields back to FASTA. Write the returned records to the curated-data directory:

REPL
julia> curated_fasta_path = joinpath(
           curated_dir,
           "bears-CYTB-curated.fasta",
       );

julia> run(
           pipeline(
               `seqkit tab2fx`;
               stdin = IOBuffer(curated_tsv),
               stdout = curated_fasta_path,
           ),
       );

julia> isfile(curated_fasta_path)
true

Read the new identifiers and confirm that every constructed label is present:

REPL
julia> curated_identifiers = split(
           chomp(
               read(
                   `seqkit seq --name --only-id $curated_fasta_path`,
                   String,
               ),
           ),
           '\n',
       );

julia> Set(curated_identifiers) == Set(sequence_labels)
true

2.7 Aligning the curated sequences

The eight records are complete representatives of the same protein-coding gene. Run mafft --auto so that MAFFT selects an alignment strategy from the size and characteristics of this input. MAFFT writes the alignment to standard output and progress information to standard error; direct them to separate files.

Shell commands

The direct shell command for this is:

Shell
$ mafft \
    --auto \
    data/curated/bears-CYTB-curated.fasta \
    > data/aligned/bears-CYTB-aligned.fasta \
    2> results/bears-CYTB-mafft.log

Set the output paths and run MAFFT from Julia:

REPL
julia> aligned_fasta_path = joinpath(
           aligned_dir,
           "bears-CYTB-aligned.fasta",
       );

julia> mafft_log_path = joinpath(
           results_dir,
           "bears-CYTB-mafft.log",
       );

julia> alignment_command = `mafft --auto $curated_fasta_path`;

julia> run(
           pipeline(
               alignment_command;
               stdout = aligned_fasta_path,
               stderr = mafft_log_path,
           ),
       );

julia> isfile(aligned_fasta_path) && isfile(mafft_log_path)
true

The alignment is the data result. The log records the MAFFT strategy and diagnostics and should remain with it.

2.8 Auditing the alignment

Inspect the saved alignment as a collection before examining individual sites:

REPL
julia> alignment_statistics = CSV.read(
           `seqkit stats --tabular --basename $aligned_fasta_path`,
           DataFrame;
           delim = '\t',
           stringtype = String,
       );

julia> select(
           alignment_statistics,
           :file,
           :type,
           :num_seqs,
           :min_len,
           :max_len,
       )
1×5 DataFrame
 Row │ file                      type    num_seqs  min_len  max_len
     │ String                    String  Int64     Int64    Int64
─────┼──────────────────────────────────────────────────────────────
   1 │ bears-CYTB-aligned.fasta  DNA            8     1140     1140

Read the aligned sequences into Julia, then verify the record count, label set, common alignment length, and divisibility of that length by three:

REPL
julia> aligned_sequences = CSV.read(
           `seqkit fx2tab --only-id --no-qual $aligned_fasta_path`,
           DataFrame;
           delim = '\t',
           header = [:label, :sequence],
           stringtype = String,
       );

julia> aligned_lengths = length.(aligned_sequences.sequence);

julia> alignment_length = only(unique(aligned_lengths))
1140

julia> observed_label_set = Set(aligned_sequences.label);

julia> expected_label_set = Set(sequence_labels);

julia> alignment_checks = (
           records = nrow(aligned_sequences),
           labels_preserved = observed_label_set == expected_label_set,
           common_length = alignment_length,
           length_divisible_by_three = alignment_length % 3 == 0,
       );

julia> alignment_checks.records
8

julia> alignment_checks.labels_preserved
true

julia> alignment_checks.common_length
1140

julia> alignment_checks.length_divisible_by_three
true

Require those properties before using the alignment downstream:

REPL
julia> @assert alignment_checks.records == expected_record_count

julia> @assert alignment_checks.labels_preserved

julia> @assert alignment_checks.length_divisible_by_three
WarningAlignment review

Equal lengths, preserved labels, and an alignment length divisible by three are structural checks. MAFFT’s nucleotide alignment does not enforce codon structure. Inspect the alignment itself, especially around gaps and rapidly changing regions, and confirm that inferred homology remains consistent with the marker, reading frame, and taxonomic scale.

3 Follow-up workflows

3.1 Summarizing aligned characters

Convert each aligned sequence to a collection of characters, then combine the sequences as columns of one matrix. Rows correspond to aligned sites:

REPL
julia> alignment_matrix = reduce(
           hcat,
           collect.(aligned_sequences.sequence),
       );

julia> size(alignment_matrix)
(1140, 8)

Count gap characters and sites with more than one observed nucleotide:

REPL
julia> gap_count = count(==('-'), alignment_matrix)
0

julia> variable_site_count = count(
           site -> length(unique(site)) > 1,
           eachrow(alignment_matrix),
       )
363

MAFFT introduces no gaps for these complete CYTB records, but 363 aligned sites vary among the eight species.

3.2 Comparing alignment strategies

For fewer than approximately 200 globally alignable sequences, the MAFFT manual describes --globalpair --maxiterate 1000 as the accuracy-oriented G-INS-i strategy. Run it as a second candidate alignment rather than overwriting the --auto result.

Shell commands

The direct shell command for this is:

Shell
$ mafft \
    --globalpair \
    --maxiterate 1000 \
    data/curated/bears-CYTB-curated.fasta \
    > data/aligned/bears-CYTB-ginsi-aligned.fasta \
    2> results/bears-CYTB-ginsi-mafft.log

Set separate output paths and run the candidate alignment from Julia:

REPL
julia> ginsi_alignment_path = joinpath(
           aligned_dir,
           "bears-CYTB-ginsi-aligned.fasta",
       );

julia> ginsi_log_path = joinpath(
           results_dir,
           "bears-CYTB-ginsi-mafft.log",
       );

julia> run(
           pipeline(
               `mafft --globalpair --maxiterate 1000 $curated_fasta_path`;
               stdout = ginsi_alignment_path,
               stderr = ginsi_log_path,
           ),
       );

Read the candidate alignment and map each label to its aligned sequence:

REPL
julia> ginsi_sequences = CSV.read(
           `seqkit fx2tab --only-id --no-qual $ginsi_alignment_path`,
           DataFrame;
           delim = '\t',
           header = [:label, :sequence],
           stringtype = String,
       );

julia> auto_by_label = Dict(
           aligned_sequences.label .=> aligned_sequences.sequence,
       );

julia> ginsi_by_label = Dict(
           ginsi_sequences.label .=> ginsi_sequences.sequence,
       );

julia> auto_by_label == ginsi_by_label
true

The two strategies produce the same alignment for these complete, closely related coding sequences. Agreement need not persist for incomplete, divergent, or structurally heterogeneous records.

3.3 Writing codon-position partitions

The reading frame begins at the first alignment position, the alignment length is divisible by three, and this alignment contains no gaps. Represent the three codon positions as stepped, one-based site ranges:

REPL
julia> partition_text = join(
           [
               "DNA, CYTB_pos1 = 1-$(alignment_length)\\3",
               "DNA, CYTB_pos2 = 2-$(alignment_length)\\3",
               "DNA, CYTB_pos3 = 3-$(alignment_length)\\3",
           ],
           '\n',
       ) * "\n";

julia> partition_path = joinpath(
           results_dir,
           "bears-CYTB-codon-partitions.txt",
       );

julia> write(partition_path, partition_text);

julia> print(partition_text)
DNA, CYTB_pos1 = 1-1140\3
DNA, CYTB_pos2 = 2-1140\3
DNA, CYTB_pos3 = 3-1140\3

The \3 step assigns every third alignment site to the same partition. See Phylogenetic inference tools – IQ-TREE for partitioned model selection and phylogenetic inference.

4 Advanced workflows

4.1 Auditing several candidate alignments

Collect the two candidate paths:

REPL
julia> alignment_paths = [
           aligned_fasta_path,
           ginsi_alignment_path,
       ];

Use map to apply the same audit to each path. The anonymous function reads one alignment, constructs its character matrix, and returns one named tuple of results. map collects those returned values in path order:

REPL
julia> alignment_audits = map(alignment_paths) do path
           records = CSV.read(
               `seqkit fx2tab --only-id --no-qual $path`,
               DataFrame;
               delim = '\t',
               header = [:label, :sequence],
               stringtype = String,
           )
           sequence_lengths = length.(records.sequence)
           characters = reduce(hcat, collect.(records.sequence))

           (
               file = basename(path),
               records = nrow(records),
               sites = only(unique(sequence_lengths)),
               gaps = count(==('-'), characters),
               variable_sites = count(
                   site -> length(unique(site)) > 1,
                   eachrow(characters),
               ),
           )
       end;

julia> alignment_audit_table = DataFrame(alignment_audits)
2×5 DataFrame
 Row │ file                            records  sites  gaps   variable_sites
     │ String                          Int64    Int64  Int64  Int64
─────┼───────────────────────────────────────────────────────────────────────
   1 │ bears-CYTB-aligned.fasta              8   1140      0             363
   2 │ bears-CYTB-ginsi-aligned.fasta        8   1140      0             363

The same pattern can audit alignments from additional methods or parameter sets. Add their paths to alignment_paths; do not infer method quality from these summary columns alone.

5 Exercises

Exercise 1

Detect an identifier mismatch

  1. Make a working copy of the raw FASTA file.
  2. Change one copied record identifier without changing its sequence.
  3. Recalculate missing_from_fasta and missing_from_mapping for the copy.
  4. Restore the accession recorded in species_by_accession before alignment.
Exercise 2

Investigate a disrupted reading frame

  1. Make another working copy of one CYTB record.
  2. Remove one nucleotide from the middle of the copied sequence.
  3. Repeat the length and translation checks.
  4. Record which checks expose the change and why the altered record should not enter the alignment.
Exercise 3

Compare another MAFFT strategy

  1. Construct an alignment with mafft --localpair --maxiterate 1000.
  2. Save its alignment and log under new filenames.
  3. Add the alignment path to alignment_paths and rebuild the audit table.
  4. Compare the aligned sequences by label, then inspect any differing sites.
