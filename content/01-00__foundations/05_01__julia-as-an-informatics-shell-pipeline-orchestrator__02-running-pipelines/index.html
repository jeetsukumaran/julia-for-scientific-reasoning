Julia as an informatics shell: Running pipelines

Author

Jeet Sukumaran

A pipeline connects the standard output of one process to the standard input of the next. Julia can construct and run the complete process sequence, capture its final result, or pause between processes to inspect and transform the intermediate data.

The examples progress from one SeqKit process to an EDirect, SeqKit, MAFFT, IQ-TREE, and PhyloMakie workflow.

1 Preparation

1.1 Installing the programs

This tutorial continues to use EDirect and SeqKit from the fundamental mechanisms tutorial.

Install each external program from its project website:

  • MAFFT provides packages and installation instructions for Linux, macOS, and Windows.
  • IQ-TREE provides IQ-TREE 3 executables for Linux, macOS, and Windows.

The commands below use the IQ-TREE 3 executable name, iqtree3. Some installations expose the executable as iqtree or iqtree2; substitute that name throughout when necessary.

TipOptional installation with Conda

Conda or Mamba can install both programs from Bioconda:

Shell
$ conda install -c bioconda mafft iqtree

Install the Julia packages and the PhyloMakie command-line application from a Julia REPL:

REPL
julia> import Pkg

julia> Pkg.add(["CSV", "DataFrames", "CairoMakie", "PhyloMakie"])

julia> Pkg.Apps.add("PhyloMakie")

Pkg.Apps.add requires Julia 1.12 or later. Ensure that ~/.julia/bin is on PATH, then confirm that every external program can be found:

Shell
$ command -v efetch seqkit mafft iqtree3 phylomakie
/home/student/edirect/efetch
/home/student/.local/bin/seqkit
/home/student/.local/bin/mafft
/home/student/.local/bin/iqtree3
/home/student/.julia/bin/phylomakie

$ iqtree3 --version
IQ-TREE version 3.1.4 for Linux x86 64-bit built Sep 10 2026

The executable paths can differ.

MAFFT aligns nucleotide or amino-acid sequences. It reads FASTA data and writes the alignment to standard output. IQ-TREE reads an alignment, infers a maximum-likelihood phylogeny, and writes a collection of analysis files. The phylomakie render command reads a phylogeny and writes a static PNG, SVG, or PDF figure.

A command-line process normally has three standard streams:

  • Standard input supplies data.
  • Standard output carries the ordinary result.
  • Standard error carries diagnostics and progress messages.

A pipeline connects standard output from one process to standard input for the next. Julia can attach files, in-memory buffers, and its own standard streams to the same connections.

2 Basic workflow

2.1 Passing program output to Julia

Use seqkit fx2tab to calculate the length and GC percentage of every sequence, then parse the program’s tab-separated output directly in Julia. --name retains the record name without the sequence, --length adds the sequence length, and --gc adds the GC percentage.

Construct the command and capture its standard output as text:

REPL
julia> sequence_statistics_command = `seqkit fx2tab --name --length --gc $fasta_path`;

julia> sequence_statistics_text = read(sequence_statistics_command, String);

julia> print(sequence_statistics_text)
NC_009492.1 1140    39.65
NC_009968.1 1140    44.30
NC_009970.1 1140    45.00
NC_009969.1 1140    44.56
NC_003426.1 1140    43.86
NC_003427.1 1140    44.30
NC_003428.1 1140    44.21
NC_009971.1 1140    45.96

The result is tab-separated data, so it can enter Julia as a table rather than as an intermediate file. Pass the command directly to CSV.read:

REPL
julia> sequence_statistics = CSV.read(
           sequence_statistics_command,
           DataFrame;
           delim = '\t',
           header = [:accession, :length, :gc],
           stringtype = String,
       )
8×3 DataFrame
 Row │ accession    length  gc
     │ String       Int64   Float64
─────┼──────────────────────────────
   1 │ NC_009492.1    1140    39.65
   2 │ NC_009968.1    1140    44.3
   3 │ NC_009970.1    1140    45.0
   4 │ NC_009969.1    1140    44.56

SeqKit calculates sequence properties. CSV.read parses its tabular standard output into typed columns. delim = '\t' identifies the field separator, header supplies the three column names, and stringtype = String stores text columns as String values. Julia can now use the parsed values directly:

julia> extrema(sequence_statistics.gc)
(39.65, 45.96)

2.2 Connecting two processes

Retain complete 1,140-nucleotide CYTB sequences, then summarize the resulting FASTA data. The first seqkit command uses --min-len 1140 and --max-len 1140 to retain records of exactly that length; --quiet suppresses extra informational messages. The second command uses seqkit stats --tabular --basename to produce one tab-separated summary row.

Construct each stage as a separate command:

REPL
julia> complete_cytb = `seqkit seq --quiet --min-len 1140 --max-len 1140 $fasta_path`;

julia> summarize_cytb = `seqkit stats --tabular --basename`;

Connect the commands with pipeline, then capture the final standard output:

REPL
julia> screening_pipeline = pipeline(complete_cytb, summarize_cytb);

julia> print(read(screening_pipeline, String))
file    format  type    num_seqs    sum_len min_len avg_len max_len
-   FASTA   DNA 8   9120    1140    1140.0  1140

pipeline(first_command, second_command) connects the first command’s standard output to the second command’s standard input. It does not start either process. read starts both processes, consumes the final output, and waits for both to finish.

Workflow alternate: Screening and summarizing sequences from the shell
Retain complete 1,140-nucleotide CYTB sequences, then summarize the resulting FASTA stream:

Shell
$ seqkit seq \
    --quiet \
    --min-len 1140 \
    --max-len 1140 \
    data/raw/bears-CYTB.fasta \
    | seqkit stats --tabular --basename
file    format  type    num_seqs    sum_len min_len avg_len max_len
-   FASTA   DNA 8   9120    1140    1140.0  1140

The first process writes FASTA records. The second process reads those records from standard input and writes one summary row.

2.3 Writing pipeline output to a file

Align the complete CYTB sequences with MAFFT and save the alignment. The complete_cytb command from the preceding workflow supplies the selected FASTA records. mafft --auto chooses an alignment strategy from the data, and /dev/stdin tells MAFFT to read those records from standard input.

Construct the MAFFT stage:

REPL
julia> alignment_command = `mafft --auto /dev/stdin`;

/dev/stdin gives MAFFT a file path that refers to its standard input on the Unix-like systems used in this course.

Connect SeqKit to MAFFT:

REPL
julia> alignment_stages = pipeline(
           complete_cytb,
           alignment_command,
       );

Set the alignment and diagnostic paths:

REPL
julia> alignment_path = joinpath(
           project_dir,
           "data",
           "working",
           "bears-CYTB-aligned.fasta",
       );

julia> alignment_log_path = joinpath(results_dir, "mafft.log");

Direct the final standard output and shared standard error to those paths, then run the pipeline:

REPL
julia> run(
           pipeline(
               alignment_stages;
               stdout = alignment_path,
               stderr = alignment_log_path,
           ),
       );

julia> isfile(alignment_path)
true

The inner pipeline connects SeqKit and MAFFT. The outer pipeline controls where their final output and diagnostics are written.

Inspect the saved alignment with SeqKit:

REPL
julia> run(`seqkit stats --tabular --basename $alignment_path`);
file    format  type    num_seqs    sum_len min_len avg_len max_len
bears-CYTB-aligned.fasta    FASTA   DNA 8   9120    1140    1140.0  1140

Workflow alternate: Aligning sequences from the shell
Send the complete coding sequences through MAFFT and save the alignment:

Shell
$ seqkit seq \
    --quiet \
    --min-len 1140 \
    --max-len 1140 \
    data/raw/bears-CYTB.fasta \
    | mafft --auto /dev/stdin \
        > data/working/bears-CYTB-aligned.fasta \
        2> results/mafft.shell.log

The shell directs MAFFT’s standard output to the alignment file and its standard error to a log.

2.4 Running a file-oriented program

Infer a maximum-likelihood phylogeny from the saved alignment. IQ-TREE reads the alignment from a file and writes the inferred Newick tree, the analysis report, and diagnostic files under one output prefix.

Set a common prefix for IQ-TREE’s output files:

REPL
julia> tree_prefix = joinpath(results_dir, "bears-CYTB");

Construct and run the IQ-TREE command:

REPL
julia> tree_command = `iqtree3 -s $alignment_path -m GTR+G -T 1 --seed 20260912 --prefix $tree_prefix`;

julia> success(pipeline(tree_command; stdout=devnull))
true

-s identifies the alignment. -m GTR+G specifies the nucleotide model, -T 1 uses one thread, and --seed records the random-number seed. --prefix determines every output path.

IQ-TREE writes the phylogeny to tree_prefix * ".treefile". It also writes the analysis report to .iqtree, diagnostics to .log, and additional analysis files under the same prefix.

success starts IQ-TREE, waits for it to finish, and returns true when the program exits successfully. stdout = devnull discards IQ-TREE’s progress output; its result files remain available under tree_prefix.

Read IQ-TREE’s Newick result from the generated .treefile:

REPL
julia> tree_path = tree_prefix * ".treefile"
"/home/student/projects/learning/scientific-julia/bear-sequence-workflows/results/bears-CYTB.treefile"

julia> newick_text = read(tree_path, String);

julia> startswith(newick_text, "(")
true

julia> endswith(chomp(newick_text), ";")
true

Workflow alternate: Inferring a maximum-likelihood phylogeny from the shell
Run IQ-TREE with the saved alignment:

Shell
$ iqtree3 \
    -s data/working/bears-CYTB-aligned.fasta \
    -m GTR+G \
    -T 1 \
    --seed 20260912 \
    --prefix results/bears-CYTB

IQ-TREE writes results/bears-CYTB.treefile, results/bears-CYTB.iqtree, results/bears-CYTB.log, and other analysis files.

2.5 Beginning a pipeline with remote data

Retrieve the annotated coding sequences from eight reviewed mitochondrial genomes, retain their CYTB records, and align the selected sequences. efetch -db nuccore selects the NCBI nucleotide database, -id receives the comma-separated accession versions, and -format fasta_cds_na returns the annotated nucleotide coding sequences. seqkit grep --by-name examines each complete FASTA header, while --use-regexp allows the \[gene=CYTB\] pattern to identify the target gene.

Represent the reviewed accession versions as a Julia collection:

REPL
julia> mitochondrial_accessions = [
           "NC_009492.1",
           "NC_009968.1",
           "NC_009970.1",
           "NC_009969.1",
           "NC_003426.1",
           "NC_003427.1",
           "NC_003428.1",
           "NC_009971.1",
       ];

julia> accession_argument = join(mitochondrial_accessions, ",");

Construct the retrieval and selection stages:

REPL
julia> retrieve_coding_sequences = `efetch -db nuccore -id $accession_argument -format fasta_cds_na`;

julia> cytb_header_pattern = raw"\[gene=CYTB\]";

julia> select_cytb = `seqkit grep --quiet --by-name --use-regexp --pattern $cytb_header_pattern`;

Connect EDirect, SeqKit, and MAFFT, then write the alignment:

REPL
julia> remote_alignment_stages = pipeline(
           retrieve_coding_sequences,
           select_cytb,
           alignment_command,
       );

julia> remote_alignment_path = joinpath(
           project_dir,
           "data",
           "working",
           "bears-CYTB.remote-aligned.fasta",
       );

julia> run(
           pipeline(
               remote_alignment_stages;
               stdout = remote_alignment_path,
               stderr = joinpath(results_dir, "remote-mafft.log"),
           ),
       );

Run IQ-TREE with the retrieved and aligned data:

REPL
julia> remote_tree_prefix = joinpath(results_dir, "bears-CYTB.remote");

julia> remote_tree_command = `iqtree3 -s $remote_alignment_path -m GTR+G -T 1 --seed 20260912 --prefix $remote_tree_prefix`;

julia> success(pipeline(remote_tree_command; stdout=devnull))
true

The NCBI request requires an internet connection. Database contents and service availability can change. The cached bears-CYTB.fasta resource supplies the same reviewed coding sequences for the remaining workflows.

Workflow alternate: Retrieving CYTB records and inferring a phylogeny from the shell
EDirect can supply the first stream. efetch -format fasta_cds_na retrieves the annotated coding sequences from eight reviewed mitochondrial genomes. SeqKit retains the records whose headers identify the CYTB gene:

Shell
$ efetch \
    -db nuccore \
    -id NC_009492.1,NC_009968.1,NC_009970.1,NC_009969.1,NC_003426.1,NC_003427.1,NC_003428.1,NC_009971.1 \
    -format fasta_cds_na \
    | seqkit grep \
        --quiet \
        --by-name \
        --use-regexp \
        --pattern '\[gene=CYTB\]' \
    | mafft --auto /dev/stdin \
        > data/working/bears-CYTB.remote-aligned.fasta \
        2> results/remote-mafft.shell.log

$ iqtree3 \
    -s data/working/bears-CYTB.remote-aligned.fasta \
    -m GTR+G \
    -T 1 \
    --seed 20260912 \
    --prefix results/bears-CYTB.remote

The sequence stream moves directly from NCBI retrieval through record selection and alignment. IQ-TREE then reads the saved alignment.

2.6 Passing a generated file to another program

Render the inferred phylogeny with the PhyloMakie command-line application. The final argument supplies IQ-TREE’s .treefile; --output sets the figure path, --force permits replacement of an existing figure, and --no-titles omits automatic titles.

Construct the rendering command with the destination path:

REPL
julia> cli_figure_path = joinpath(results_dir, "bears-CYTB.svg");

julia> render_command = `phylomakie render --output $cli_figure_path --force --no-titles $tree_path`;

Run the command:

REPL
julia> run(render_command);
/home/student/projects/learning/scientific-julia/bear-sequence-workflows/results/bears-CYTB.svg

julia> isfile(cli_figure_path)
true

Julia starts PhyloMakie and waits for it to write the figure.

Workflow alternate: Rendering an inferred phylogeny from the shell
Pass IQ-TREE’s .treefile to the PhyloMakie command-line renderer:

Shell
$ phylomakie render \
    --output results/bears-CYTB.shell.svg \
    --force \
    --no-titles \
    results/bears-CYTB.treefile
results/bears-CYTB.shell.svg

IQ-TREE retains the analysis report and log while PhyloMakie reads the Newick tree from results/bears-CYTB.treefile.

3 Follow-up workflows

3.1 Inserting Julia between processes

A direct pipeline works while each program can consume the preceding program’s output. Here, Julia transforms the labels, MAFFT writes the alignment required by IQ-TREE, and IQ-TREE writes the inferred phylogeny:

SeqKit → Julia → SeqKit → MAFFT → file → IQ-TREE → Julia

The accession identifiers in the cached FASTA file preserve links to the NCBI records. Replace them with species labels before alignment and tree inference.

3.1.1 Capturing an intermediate representation

seqkit fx2tab represents each FASTA record as one tab-separated row:

REPL
julia> tabular_sequences = read(
           `seqkit fx2tab $fasta_path`,
           String,
       );

julia> sequence_rows = split(chomp(tabular_sequences), '\n');

julia> length(sequence_rows)
8

Each row contains the accession, nucleotide sequence, and an empty FASTQ quality field.

3.1.2 Transforming the intermediate data

Create the accession-to-label mapping:

REPL
julia> label_by_accession = Dict(
           "NC_009492.1" => "Ailuropoda_melanoleuca",
           "NC_009968.1" => "Helarctos_malayanus",
           "NC_009970.1" => "Melursus_ursinus",
           "NC_009969.1" => "Tremarctos_ornatus",
           "NC_003426.1" => "Ursus_americanus",
           "NC_003427.1" => "Ursus_arctos",
           "NC_003428.1" => "Ursus_maritimus",
           "NC_009971.1" => "Ursus_thibetanus",
       );

Apply the mapping to each tabular sequence row:

REPL
julia> renamed_rows = map(sequence_rows) do row
           fields = split(row, '\t')
           accession = fields[1]
           sequence = fields[2]
           "$(label_by_accession[accession])\t$sequence"
       end;

julia> renamed_table = join(renamed_rows, '\n') * "\n";

The anonymous function receives one row, separates its fields, looks up the species label, and returns a replacement row. The sequence itself is unchanged.

3.1.3 Returning data to an external process

seqkit tab2fx converts the transformed rows back to FASTA:

REPL
julia> renamed_fasta = read(
           pipeline(
               `seqkit tab2fx`;
               stdin = IOBuffer(renamed_table),
           ),
           String,
       );

julia> renamed_identifiers = read(
           pipeline(
               `seqkit seq --name --only-id`;
               stdin = IOBuffer(renamed_fasta),
           ),
           String,
       );

julia> print(renamed_identifiers)
Ailuropoda_melanoleuca
Helarctos_malayanus
Melursus_ursinus
Tremarctos_ornatus
Ursus_americanus
Ursus_arctos
Ursus_maritimus
Ursus_thibetanus

The first external process consumes Julia’s transformed text and returns FASTA. The second confirms the new record identifiers.

3.1.4 Resuming a pipeline

Supply the renamed FASTA string to MAFFT and write the alignment required by IQ-TREE:

REPL
julia> species_alignment_path = joinpath(
           project_dir,
           "data",
           "working",
           "bears-CYTB-species-aligned.fasta",
       );

julia> species_alignment_pipeline = pipeline(
           alignment_command;
           stdin = IOBuffer(renamed_fasta),
           stdout = species_alignment_path,
           stderr = joinpath(results_dir, "species-mafft.log"),
       );

julia> run(species_alignment_pipeline);

julia> isfile(species_alignment_path)
true

3.1.5 Running the next file-oriented process

Run IQ-TREE with the species-labelled alignment:

REPL
julia> species_tree_prefix = joinpath(results_dir, "bears-CYTB-species");

julia> species_tree_command = `iqtree3 -s $species_alignment_path -m GTR+G -T 1 --seed 20260912 --prefix $species_tree_prefix`;

julia> success(pipeline(species_tree_command; stdout=devnull))
true

julia> species_tree_path = species_tree_prefix * ".treefile";

julia> species_newick = read(species_tree_path, String);

julia> occursin("Ailuropoda_melanoleuca", species_newick)
true

3.1.6 Consuming the final result in Julia

Parse the Newick string directly and plot the resulting phylogeny:

REPL
julia> phylogeny = parsephylogeny(
           NewickFormat(),
           species_newick,
       );

julia> figure_axis_plot = plot(
           phylogeny;
           useedgelength = true,
           tipoffset = 0.01,
           xlim = (0.95, 1.80),
       );

julia> figure_axis_plot.figure

Save the figure at a known path:

REPL
julia> figure_path = joinpath(
           results_dir,
           "bears-CYTB-species.png",
       );

julia> save(figure_path, figure_axis_plot.figure);

julia> isfile(figure_path)
true

Julia reads the IQ-TREE .treefile. parsephylogeny constructs the phylogeny value, and PhyloMakie returns a figure that remains available for further analysis or composition.

3.2 Redirecting standard error

Standard error should remain separate from ordinary data. Capture it when the diagnostics need inspection:

REPL
julia> alignment_log_path = joinpath(results_dir, "alignment-only.log");

julia> alignment_pipeline = pipeline(
           alignment_command;
           stdin = IOBuffer(renamed_fasta),
           stderr = alignment_log_path,
       );

julia> aligned_fasta = read(alignment_pipeline, String);

julia> isfile(alignment_log_path)
true

The FASTA alignment enters Julia through standard output. MAFFT’s strategy and progress messages enter the log through standard error.

3.3 Reusing command stages

A Cmd value can participate in several process sequences:

REPL
julia> alignment_only = pipeline(
           alignment_command;
           stdin = IOBuffer(renamed_fasta),
           stderr = devnull,
       );

julia> aligned_fasta = read(alignment_only, String);

julia> alignment_statistics = read(
           pipeline(
               `seqkit stats --tabular --basename`;
               stdin = IOBuffer(aligned_fasta),
           ),
           String,
       );

julia> print(alignment_statistics)
file    format  type    num_seqs    sum_len min_len avg_len max_len
-   FASTA   DNA 8   9120    1140    1140.0  1140

The same alignment output can be inspected with SeqKit or supplied to a tree inference program.

4 Advanced workflows

4.1 Constructing a pipeline from a command collection

Store the external stages in a vector:

REPL
julia> stages = [
           complete_cytb,
           alignment_command,
       ]
2-element Vector{Cmd}:
 `seqkit seq --quiet --min-len 1140 --max-len 1140 /home/student/projects/learning/scientific-julia/bear-sequence-workflows/data/raw/bears-CYTB.fasta`
 `mafft --auto /dev/stdin`

Expand the collection into the positional arguments accepted by pipeline:

REPL
julia> constructed_pipeline = pipeline(stages...);

julia> constructed_alignment = read(
           pipeline(constructed_pipeline; stderr=devnull),
           String,
       );

julia> count(==('>'), constructed_alignment)
8

The ... operator supplies the two stored commands as two pipeline arguments.

4.2 Applying a pipeline to a collection

Define two record-selection specifications:

REPL
julia> workflow_specs = [
           (name = "all-bears", pattern = ".+"),
           (name = "NC_003-accessions", pattern = "^NC_003"),
       ];
