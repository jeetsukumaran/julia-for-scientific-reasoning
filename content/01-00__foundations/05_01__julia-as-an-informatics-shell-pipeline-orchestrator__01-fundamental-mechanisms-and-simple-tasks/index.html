Julia as an informatics shell: Fundamental mechanisms and simple tasks

Author

Jeet Sukumaran

Julia can start command-line programs, pass arguments to them, supply input, and capture their results. This is useful when an established informatics program provides an operation that Julia does not provide directly.

This tutorial uses NCBI Entrez Direct (EDirect) and SeqKit. The examples begin with one external process at a time. Later tutorials connect these processes into longer workflows.

1 Preparation

1.1 Installing EDirect and SeqKit

Install each program from its project website:

  • EDirect provides an installer for Linux, macOS, and Windows Subsystem for Linux.
  • SeqKit provides precompiled executables for Linux, macOS, and Windows.

Add the installed executable directories to PATH, then open a new terminal.

TipOptional installation with Conda

Conda or Mamba can install both programs from Bioconda:

Shell
$ conda install -c bioconda entrez-direct seqkit

Confirm that the programs can be found:

Shell
$ command -v esearch efetch seqkit
/home/student/edirect/esearch
/home/student/edirect/efetch
/home/student/.local/bin/seqkit

$ seqkit version
seqkit v2.13.0

The paths and installed version can differ.

EDirect searches and retrieves records from NCBI databases. Its programs include esearch for database searches and efetch for record retrieval. The EDirect tutorial develops those operations.

SeqKit reads FASTA and FASTQ data. Its subcommands inspect, select, transform, and summarize sequence records. Most SeqKit commands accept file paths or standard input and write their results to standard output.

1.2 Acquiring the example data

Download these two course resources:

  • Bear CYTB sequences
  • Sequence inventory

The FASTA file contains one 1,140-nucleotide mitochondrial CYTB coding sequence for each of eight extant bear species. Its record identifiers are NCBI accession versions. The inventory maps those accessions to species names.

Create the workshop project directories:

Shell
$ mkdir -p /home/student/projects/learning/scientific-julia/bear-sequence-workflows/data/raw
$ mkdir -p /home/student/projects/learning/scientific-julia/bear-sequence-workflows/data/working
$ mkdir -p /home/student/projects/learning/scientific-julia/bear-sequence-workflows/results
$ cd /home/student/projects/learning/scientific-julia/bear-sequence-workflows

Save bears-CYTB.fasta and _INVENTORY.tsv under data/raw, then start Julia from the project directory:

Shell
$ julia --project=.

Represent the project and input paths as Julia strings:

REPL
julia> project_dir = "/home/student/projects/learning/scientific-julia/bear-sequence-workflows"
"/home/student/projects/learning/scientific-julia/bear-sequence-workflows"

julia> fasta_path = joinpath(project_dir, "data", "raw", "bears-CYTB.fasta")
"/home/student/projects/learning/scientific-julia/bear-sequence-workflows/data/raw/bears-CYTB.fasta"

julia> isfile(fasta_path)
true

All relative paths below are resolved from the workshop project directory.

2 Basic workflow

2.1 Constructing and running a command

Use seqkit stats to inspect the number and lengths of the sequences in the FASTA file. --tabular requests tab-separated output, and --basename reports the filename rather than the complete input path.

Construct the command with backticks:

REPL
julia> statistics_command = `seqkit stats --tabular --basename $fasta_path`
`seqkit stats --tabular --basename /home/student/projects/learning/scientific-julia/bear-sequence-workflows/data/raw/bears-CYTB.fasta`

julia> typeof(statistics_command)
Cmd

Backticks construct a Cmd value. They do not run the program. The $fasta_path expression inserts the path as one command argument.

Pass the command to run:

REPL
julia> run(statistics_command);
file    format  type    num_seqs    sum_len min_len avg_len max_len
bears-CYTB.fasta    FASTA   DNA 8   9120    1140    1140.0  1140

run starts SeqKit and waits for it to finish. SeqKit’s standard output appears in the REPL as the program produces it.

NoteCommand arguments

Julia starts the executable directly. It does not insert a shell between Julia and SeqKit.

An interpolated string remains one argument even when it contains spaces. An interpolated collection expands into several arguments.

Workflow alternate: Inspecting a sequence file from the shell
Run seqkit stats with the FASTA path as its input argument:

Shell
$ seqkit stats --tabular --basename data/raw/bears-CYTB.fasta
file    format  type    num_seqs    sum_len min_len avg_len max_len
bears-CYTB.fasta    FASTA   DNA 8   9120    1140    1140.0  1140

--tabular requests tab-separated output. --basename reports only the filename rather than the complete input path.

2.2 Capturing output as text

Read the FASTA identifiers into Julia. seqkit seq --name writes record names without their sequences, and --only-id omits any description following each identifier.

Construct the command and capture its standard output with read(command, String):

REPL
julia> identifier_command = `seqkit seq --name --only-id $fasta_path`;

julia> identifier_text = read(identifier_command, String)
"NC_009492.1\nNC_009968.1\nNC_009970.1\nNC_009969.1\nNC_003426.1\nNC_003427.1\nNC_003428.1\nNC_009971.1\n"

The first argument tells read where the data comes from. The second argument requests one String. read starts the command, waits for it to finish, and returns its complete standard output.

Split the text at line endings when the individual identifiers are needed:

REPL
julia> accessions = split(chomp(identifier_text), '\n')
8-element Vector{SubString{String}}:
 "NC_009492.1"
 "NC_009968.1"
 "NC_009970.1"
 "NC_009969.1"
 "NC_003426.1"
 "NC_003427.1"
 "NC_003428.1"
 "NC_009971.1"

chomp removes the final line ending. split returns one element for each remaining line.

Workflow alternate: Reading sequence identifiers from the shell

seqkit seq --name --only-id writes one FASTA identifier per line:

Shell
$ seqkit seq --name --only-id data/raw/bears-CYTB.fasta
NC_009492.1
NC_009968.1
NC_009970.1
NC_009969.1
NC_003426.1
NC_003427.1
NC_003428.1
NC_009971.1

2.3 Capturing a single value

Count the records whose identifiers begin with NC_003. seqkit grep selects matching records; --use-regexp treats the supplied pattern as a regular expression, and --count returns only the number of matches. The initial ^ anchors the match at the beginning of each identifier.

Capture the one-line result with readchomp, then parse the text as an integer:

REPL
julia> accession_pattern = "^NC_003";

julia> count_command = `seqkit grep --use-regexp --pattern $accession_pattern --count $fasta_path`;

julia> matching_record_count = parse(Int, readchomp(count_command))
3

readchomp removes one trailing line ending. parse(Int, ...) converts the captured text to an integer that Julia can use in later calculations.

Workflow alternate: Counting matching records from the shell
Count identifiers beginning with NC_003:

Shell
$ seqkit grep --use-regexp --pattern '^NC_003' --count data/raw/bears-CYTB.fasta
3

--use-regexp treats the pattern as a regular expression. The initial ^ anchors the match at the beginning of each identifier.

2.4 Writing program output to a file

Select three sequence records and save them as a new FASTA file. The seqkit grep subcommand reads one accession per line from the path supplied to --pattern-file and writes matching FASTA records to standard output. --quiet suppresses extra informational messages.

Create the accession collection and write the pattern file with Julia’s write function:

REPL
julia> selected_accessions = [
           "NC_009492.1",
           "NC_003427.1",
           "NC_003428.1",
       ];

julia> pattern_path = joinpath("data", "working", "selected-accessions.txt")
"data/working/selected-accessions.txt"

julia> write(pattern_path, join(selected_accessions, '\n') * "\n");

Construct the SeqKit command:

REPL
julia> selection_command = `seqkit grep --quiet --pattern-file $pattern_path $fasta_path`;

julia> selected_fasta_path = joinpath(
           "data",
           "working",
           "selected-bears-CYTB.fasta",
       )
"data/working/selected-bears-CYTB.fasta"

Use pipeline(command; stdout=path) to connect standard output to the destination. This form describes the connection; run starts the process:

REPL
julia> run(pipeline(selection_command; stdout=selected_fasta_path));

julia> readchomp(`seqkit grep --use-regexp --pattern .+ --count $selected_fasta_path`)
"3"

The output remains FASTA data throughout the operation. Julia controls its destination without parsing or rewriting the sequence records.

Workflow alternate: Selecting sequence records from the shell
Store three accessions in a pattern file, then retrieve their FASTA records:

Shell
$ printf '%s\n' \
    NC_009492.1 \
    NC_003427.1 \
    NC_003428.1 \
    > data/working/selected-accessions.txt

$ seqkit grep \
    --quiet \
    --pattern-file data/working/selected-accessions.txt \
    data/raw/bears-CYTB.fasta \
    > data/working/selected-bears-CYTB.fasta

$ seqkit stats --tabular --basename data/working/selected-bears-CYTB.fasta
file    format  type    num_seqs    sum_len min_len avg_len max_len
selected-bears-CYTB.fasta   FASTA   DNA 3   3420    1140    1140.0  1140

The shell’s > operator connects a program’s standard output to a file.

2.5 Supplying standard input

Select records from an in-memory accession collection without first creating a pattern file. SeqKit accepts - as the --pattern-file path, which tells seqkit grep to read the patterns from standard input.

Create the identifier stream as a Julia string:

REPL
julia> in_memory_accessions = ["NC_009492.1", "NC_003428.1"];

julia> pattern_text = join(in_memory_accessions, '\n') * "\n"
"NC_009492.1\nNC_003428.1\n"

Wrap the string in an IOBuffer, then attach that stream to the command’s standard input:

REPL
julia> selection_from_memory = pipeline(
           `seqkit grep --quiet --pattern-file - $fasta_path`;
           stdin = IOBuffer(pattern_text),
       );

julia> selected_fasta = read(selection_from_memory, String);

julia> count(==('>'), selected_fasta)
2

IOBuffer(pattern_text) presents the in-memory text as a readable stream. SeqKit reads its patterns from that stream and reads the FASTA records from the path argument.

TipChoosing an execution function
  • run(command) forwards output to the REPL.
  • read(command, String) returns the complete standard output.
  • readchomp(command) returns text with one trailing line ending removed.
  • success(command) returns whether the process exited successfully.

The first three forms throw ProcessFailedException when a command exits unsuccessfully.

Workflow alternate: Supplying record identifiers from the shell
SeqKit accepts - as the pattern-file path to read identifiers from standard input:

Shell
$ printf '%s\n' NC_009492.1 NC_003428.1 \
    | seqkit grep \
        --quiet \
        --pattern-file - \
        data/raw/bears-CYTB.fasta

The pipe connects the output from printf to SeqKit’s standard input.

3 Follow-up workflows

3.1 Locating programs

Sys.which returns the executable that Julia will run:

REPL
julia> Sys.which("seqkit")
"/home/student/.local/bin/seqkit"

julia> Sys.which("program-that-is-not-installed") === nothing
true

Check required programs before starting a long workflow.

3.2 Checking paths

Julia provides direct filesystem predicates:

REPL
julia> isfile(fasta_path)
true

julia> isdir(joinpath(project_dir, "results"))
true

julia> ispath(joinpath(project_dir, "data", "raw", "missing.fasta"))
false

Use isfile for regular files, isdir for directories, and ispath for either kind of filesystem entry.

3.3 Listing and locating files

readdir lists the immediate contents of a directory:

REPL
julia> readdir(joinpath(project_dir, "data"); join=true)
2-element Vector{String}:
 "/home/student/projects/learning/scientific-julia/bear-sequence-workflows/data/raw"
 "/home/student/projects/learning/scientific-julia/bear-sequence-workflows/data/working"

walkdir visits a directory tree. A comprehension can retain only FASTA paths:

REPL
julia> fasta_paths = [
           joinpath(directory, filename)
           for (directory, _, filenames) in walkdir(joinpath(project_dir, "data"))
           for filename in filenames
           if endswith(filename, ".fasta")
       ]
2-element Vector{String}:
 "/home/student/projects/learning/scientific-julia/bear-sequence-workflows/data/raw/bears-CYTB.fasta"
 "/home/student/projects/learning/scientific-julia/bear-sequence-workflows/data/working/selected-bears-CYTB.fasta"

The underscore marks the reported subdirectory names as deliberately unused.

3.4 Copying and renaming files

Use Julia’s filesystem functions rather than starting external programs for ordinary file operations:

REPL
julia> copy_path = joinpath("data", "working", "selected-bears-CYTB.copy.fasta");

julia> cp(selected_fasta_path, copy_path)
"data/working/selected-bears-CYTB.copy.fasta"

julia> review_path = joinpath("data", "working", "selected-bears-CYTB.review.fasta");

julia> mv(copy_path, review_path)
"data/working/selected-bears-CYTB.review.fasta"

julia> isfile(review_path)
true

Both functions return the destination path. By default, they stop when the destination already exists.

3.5 Running a command in another directory

A Cmd can specify the external process’s working directory:

REPL
julia> local_statistics = Cmd(
           `seqkit stats --tabular --basename bears-CYTB.fasta`;
           dir = dirname(fasta_path),
       );

julia> run(local_statistics);
file    format  type    num_seqs    sum_len min_len avg_len max_len
bears-CYTB.fasta    FASTA   DNA 8   9120    1140    1140.0  1140

julia> pwd()
"/home/student/projects/learning/scientific-julia/bear-sequence-workflows"

The dir setting affects SeqKit. Julia’s working directory does not change.

3.6 Supplying an environment variable

SeqKit reads SEQKIT_THREADS when its thread count is not given as a command argument:

REPL
julia> two_thread_statistics = addenv(
           statistics_command,
           "SEQKIT_THREADS" => "2",
       );

julia> success(pipeline(two_thread_statistics; stdout=devnull))
true

addenv returns a new command. It does not modify Julia’s ENV mapping.

4 Advanced workflows

4.1 Applying a command to a collection

Create one FASTA file for each selected accession:

REPL
julia> record_dir = joinpath("data", "working", "individual-records");

julia> mkpath(record_dir);

julia> record_paths = map(selected_accessions) do accession
           output_path = joinpath(record_dir, accession * ".fasta")
           command = `seqkit grep --quiet --pattern $accession $fasta_path`
           run(pipeline(command; stdout=output_path))
           output_path
       end
3-element Vector{String}:
 "data/working/individual-records/NC_009492.1.fasta"
 "data/working/individual-records/NC_003427.1.fasta"
 "data/working/individual-records/NC_003428.1.fasta"

map calls the anonymous do function once for each accession. Each call constructs a command, writes one matching record, and returns its output path. The resulting vector preserves the accession order.

4.2 Constructing commands before running them

Commands can be collected and inspected before any external process starts:

REPL
julia> any_identifier_pattern = ".+";

julia> count_commands = map(
           path -> `seqkit grep --use-regexp --pattern $any_identifier_pattern --count $path`,
           record_paths,
       )
3-element Vector{Cmd}:
 `seqkit grep --use-regexp --pattern .+ --count data/working/individual-records/NC_009492.1.fasta`
 `seqkit grep --use-regexp --pattern .+ --count data/working/individual-records/NC_003427.1.fasta`
 `seqkit grep --use-regexp --pattern .+ --count data/working/individual-records/NC_003428.1.fasta`

julia> record_counts = map(
           command -> parse(Int, readchomp(command)),
           count_commands,
       )
3-element Vector{Int64}:
 1
 1
 1

The first map constructs commands. The second runs each command and converts its result to an integer.

5 Exercises

Exercise 1

Inspect another sequence property

  1. Run seqkit fx2tab --help.
  2. Select one additional sequence property.
  3. Construct the corresponding command in Julia.
  4. Capture and inspect its output.
Exercise 2

Select another record set

  1. Store four accession versions in a Julia vector.
  2. Write the vector to a pattern file.
  3. Use SeqKit to create a four-record FASTA file.
  4. Confirm the record count with seqkit grep --count.
Exercise 3

Process a collection

  1. Select four accessions.
  2. Use map to create one FASTA file for each accession.
  3. Return the four output paths.
  4. Confirm that every path identifies a file.
