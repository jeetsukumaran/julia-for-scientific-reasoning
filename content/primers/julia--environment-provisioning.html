Julia – Environment provisioning

Author

Jeet Sukumaran

1 Provisioning a Julia environment

A Julia environment specifies the packages, and the particular versions of those packages, available to a Julia program. Provisioning an environment means preparing it with all the packages required by a program, analysis, or project.

Julia can maintain many independent environments on the same computer. These may include the default global environment, a general-purpose scratch environment, and dedicated project environments. Package-management commands always operate on the environment that is currently active, so the first step in provisioning an environment is to make sure that the intended environment is active.

using Pkg

Base.active_project()
Pkg.status()

Base.active_project() returns the path to the Project.toml file for the active environment. Pkg.status() identifies that same project and lists its direct package dependencies.

If a project directory should provide the environment, activate that directory before adding or installing anything:

using Pkg

Pkg.activate(".")

Here, "." means the current working directory. The equivalent command-line form is to start Julia with the project already active:

julia --project=.

For a fuller discussion of when to use shared or project-specific environments, see Julia – Environments – Global vs project.

2 Adding packages to a new or existing environment

Use Pkg.add to add a registered package to the active environment:

using Pkg

Pkg.add("GLMakie")

Multiple registered packages can be added together:

Pkg.add(["DataFrames", "CSV", "GLMakie"])

Some packages are available from a public source repository but have not yet been registered in Julia’s General registry. These packages need to be added using their repository URL. For example, PhyloMakie.jl is currently installed directly from GitHub:

Pkg.add(url = "https://github.com/JuliaPhylo/PhyloMakie.jl")

Pkg.add records the package as a direct dependency in the active environment’s Project.toml and resolves a compatible set of package versions in Manifest.toml. Use Pkg.add rather than editing either file manually.

A package can already be downloaded somewhere on the computer but still not be available in the active environment. Julia stores downloaded package source code in a shared depot, while each environment separately records which packages it can use. Adding a package to the active environment establishes that environment-specific dependency; Julia reuses the downloaded package source when a suitable copy is already available.

3 Provisioning an existing project

When a project already provides Project.toml and Manifest.toml, do not add each dependency again individually. Activate the project and instantiate its environment:

using Pkg

Pkg.activate(".")
Pkg.instantiate()

Pkg.instantiate() reads the existing project files, downloads any required packages that are missing from the computer, and prepares the environment using the versions recorded in Manifest.toml. If the environment is already fully provisioned, it makes no changes.

If the project contains Project.toml but no Manifest.toml, Pkg.instantiate() resolves a compatible set of package versions and creates a new manifest. This prepares a usable environment, but it does not necessarily reproduce the exact versions used previously by another person or on another computer.

The same operation can be run directly from the shell:

julia --project=. -e 'using Pkg; Pkg.instantiate()'

4 A compact provisioning workflow

For a new project environment:

using Pkg

Pkg.activate(".")
Pkg.add("GLMakie")
Pkg.add(url = "https://github.com/JuliaPhylo/PhyloMakie.jl")
Pkg.status()

For an existing project environment:

using Pkg

Pkg.activate(".")
Pkg.instantiate()
Pkg.status()

In both cases, check the active project before provisioning it. This avoids accidentally installing packages into the global environment or into a different project’s environment.
