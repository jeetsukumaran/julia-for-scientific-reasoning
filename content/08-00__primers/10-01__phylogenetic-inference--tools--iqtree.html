Phylogenetic inference tools – IQ-TREE

Author

Jeet Sukumaran

IQ-TREE infers maximum-likelihood phylogenies from aligned molecular or discrete-character data. A typical analysis selects or specifies an evolutionary model, searches for the maximum-likelihood tree, estimates branch support, and writes the tree in Newick format.

1 Installation and command names

Download a current binary from the IQ-TREE website or use one of the package-manager methods in the installation guide.

The commands below use the IQ-TREE 3 executable name, iqtree3. Some installations expose the executable as iqtree or iqtree2; substitute that name in each command if necessary.

Confirm the installed version and display the command-line help:

iqtree3 --version
iqtree3 -h

Record the version reported by --version with the analysis results.

2 Input requirements

IQ-TREE requires a multiple-sequence alignment, not raw unaligned sequences. It accepts FASTA, PHYLIP, NEXUS, CLUSTAL, and MSF alignments.

Before starting an analysis, confirm that:

  • every sequence represents homologous characters and has the same aligned length;
  • every taxon has a unique, compact label;
  • taxon labels avoid spaces and Newick punctuation such as parentheses, commas, colons, and semicolons;
  • the alignment contains the intended character type;
  • partition coordinates, if used, are one-based and match the alignment; and
  • constant sites remain present unless the sampling process deliberately retained only variable sites.

IQ-TREE treats gaps and missing or ambiguous characters as unknown states. Unsupported characters in taxon labels may be replaced with underscores, which can create duplicate labels. Correct such labels in the input alignment before analysis.

3 A standard analysis

The following command selects a model, searches for a maximum-likelihood tree, and calculates two forms of branch support:

iqtree3 \
    -s alignment.fasta \
    -m MFP \
    -B 1000 \
    --alrt 1000 \
    -T AUTO \
    --seed 20260912 \
    --prefix alignment_run1

The parameters have the following meanings:

Parameter Meaning
-s alignment.fasta Reads the multiple-sequence alignment from alignment.fasta.
-m MFP Runs ModelFinder Plus, selects the best-fit model by the Bayesian information criterion by default, and uses that model for tree inference.
-B 1000 Runs 1,000 ultrafast bootstrap (UFBoot) replicates. IQ-TREE recommends at least 1,000 replicates.
--alrt 1000 Runs 1,000 replicates of the SH-like approximate likelihood-ratio test (SH-aLRT).
-T AUTO Benchmarks available CPU threads and selects an efficient thread count. On a managed cluster, replace AUTO with the number of CPU threads allocated to the job.
--seed 20260912 Sets the random-number seed. Any fixed integer may be used. Record the IQ-TREE version and computing environment because a seed alone does not guarantee identical results across versions or platforms.
--prefix alignment_run1 Writes all output files with the prefix alignment_run1 instead of deriving their names from the alignment filename. Use a distinct prefix for every analysis.

-m MFP is the default behavior in modern IQ-TREE versions, but stating it explicitly records the model-selection procedure in the command.

4 Model selection and model strings

Run model selection without a subsequent full tree search when the selected model is needed for a separate workflow:

iqtree3 \
    -s alignment.fasta \
    -m MF \
    -T AUTO \
    --prefix alignment_model_test

-m MF performs ModelFinder model selection only. Read the selected model from alignment_model_test.iqtree. Supply that model directly in a later analysis:

iqtree3 \
    -s alignment.fasta \
    -m GTR+F+R4 \
    -B 1000 \
    --alrt 1000 \
    -T AUTO \
    --seed 20260912 \
    --prefix alignment_gtr_f_r4

An IQ-TREE model string combines a base substitution model with optional components:

Component Meaning
GTR, HKY, JC Examples of nucleotide substitution models.
LG, WAG, JTT Examples of amino-acid exchangeability models.
+F Uses empirical character frequencies counted from the alignment.
+FO Optimizes character frequencies by maximum likelihood.
+I Estimates a proportion of invariable sites.
+G4 Models among-site rate variation with a discrete gamma distribution and four rate categories.
+R4 Models among-site rate variation with four FreeRate categories.
+ASC Corrects for ascertainment bias when the input deliberately excludes constant sites, as in many SNP or morphological matrices.

Do not add model components by convention alone. Use ModelFinder or provide a biological and statistical reason for fixing a model. +ASC is incompatible with an alignment that contains constant sites.

5 Character types

IQ-TREE usually detects the character type. Use --seqtype when detection is incorrect or when the intended analysis requires an explicit type:

Parameter Character type
--seqtype DNA Nucleotide data.
--seqtype AA Amino-acid data.
--seqtype CODON Protein-coding nucleotide data analyzed with the standard genetic code and a codon model.
--seqtype CODON5 Codon data using genetic-code table 5, the invertebrate mitochondrial code.
--seqtype MORPH Discrete morphological characters.

Codon analysis requires --seqtype CODON or the appropriate numbered genetic code. The alignment length must be divisible by three, and the first alignment position must correspond to the first codon position.

For an alignment that contains only ascertained variable nucleotide sites:

iqtree3 \
    -s snps.fasta \
    --seqtype DNA \
    -m MFP+ASC \
    -B 1000 \
    --alrt 1000 \
    -T AUTO \
    --seed 20260912 \
    --prefix snps_run1

6 Partitioned alignments

Partition a concatenated alignment when defined site sets, such as genes or codon positions, require separate evolutionary models. A RAxML-style partition file named partitions.txt can contain:

DNA, gene1_pos1 = 1-900\3
DNA, gene1_pos2 = 2-900\3
DNA, gene1_pos3 = 3-900\3
DNA, gene2 = 901-1500

The expression 1-900\3 selects sites 1, 4, 7, and so forth through site 898. The other two expressions select the second and third codon positions.

Run an edge-proportional partition analysis and allow ModelFinder to merge similar partitions:

iqtree3 \
    -s concatenated.fasta \
    -p partitions.txt \
    -m MFP+MERGE \
    -B 1000 \
    --alrt 1000 \
    -T AUTO \
    --seed 20260912 \
    --prefix concatenated_partitioned

The partition parameters differ in how they model branch lengths:

Parameter Partition model
-q partitions.txt Uses one shared set of branch lengths for all partitions.
-p partitions.txt Uses a shared topology and proportional branch lengths, allowing each partition to have a different overall evolutionary rate. This is the usual starting point for a partitioned analysis.
-Q partitions.txt Uses a shared topology but an independent set of branch lengths for each partition. This model has many more parameters.
-m MFP+MERGE Selects models, searches for a lower-dimensional partitioning scheme by merging compatible partitions, and then infers the tree.

Inspect the selected models and merged partition scheme in the .iqtree report and the generated .best_scheme.nex file.

7 Starting trees, constraints, and fixed trees

These parameters have distinct effects:

Parameter Effect
-t start.tree Starts the search from the supplied Newick tree. The topology may change during the search.
-g constraint.tree Restricts the search to trees compatible with the supplied, possibly partial, topological constraint.
-t fixed.tree --tree-fix Fixes the supplied topology, skips the topology search, and estimates its likelihood and other model quantities.
-o Outgroup Places the named taxon on the outgroup side of the reported tree. Under a reversible substitution model, this does not supply statistical information about the root.

Use constraints only when they represent an explicit analysis assumption. A starting tree is not a constraint.

8 Resource limits

Use a fixed thread count and memory limit when a scheduler or shared computer assigns finite resources:

iqtree3 \
    -s alignment.fasta \
    -m MFP \
    -B 1000 \
    --alrt 1000 \
    -T 8 \
    --mem 16G \
    --seed 20260912 \
    --prefix alignment_run1

-T 8 uses up to eight CPU threads. --mem 16G limits IQ-TREE to approximately 16 GB of memory. These values must not exceed the resources allocated to the process.

9 Output files

For --prefix alignment_run1, the main files are:

File Contents
alignment_run1.treefile Best maximum-likelihood tree in Newick format, including requested branch-support labels.
alignment_run1.iqtree Main report with the input summary, selected model, estimated parameters, log-likelihood, branch-support legend, textual tree, and relevant citation list.
alignment_run1.log Complete run log, including the IQ-TREE version, command, progress, warnings, and completion status.
alignment_run1.ckp.gz Checkpoint used to resume an interrupted analysis.
alignment_run1.model.gz ModelFinder checkpoint and model-test results when model selection is performed.
alignment_run1.contree Consensus tree produced by an ultrafast bootstrap analysis.
alignment_run1.splits.nex Bootstrap split frequencies in NEXUS format.

Read the report and log before using the tree:

less alignment_run1.iqtree
less alignment_run1.log

Confirm the following information:

  • the program completed normally;
  • the detected character type and alignment dimensions are correct;
  • the selected model or partition scheme is the intended one;
  • warnings about duplicate sequences, composition, missing data, or numerical behavior have been evaluated;
  • the maximum log-likelihood and random-number seed are recorded; and
  • the branch-support label order matches the legend in the .iqtree report.

10 Branch-support labels

When --alrt 1000 and -B 1000 are combined, internal branch labels normally have the form:

SH-aLRT/UFBoot

A label of 87.4/98 therefore reports 87.4% SH-aLRT support followed by 98% ultrafast bootstrap support.

For a single-gene tree, the IQ-TREE documentation treats SH-aLRT support of at least 80% together with UFBoot support of at least 95% as strong support. These thresholds do not transfer directly to concatenated phylogenomic analyses, where support values can become uniformly high. Examine gene and site concordance factors for multi-locus data, and treat all branch-support values as measures conditional on the alignment, model, and analysis procedure.

11 Checkpoints and repeated analyses

IQ-TREE periodically writes the .ckp.gz checkpoint. If a run stops before completion, rerun the same command with the same input and prefix to resume it.

A completed checkpoint prevents accidental overwriting. To conduct another analysis, use a new prefix. The --redo parameter discards the completed checkpoint state and overwrites files for the existing prefix; use it only when the existing result is no longer needed.

For analyses susceptible to local optima, add --runs 10 to perform ten independent tree searches in one invocation, or run separate commands with different seeds and prefixes. Compare the final log-likelihoods and topologies, and retain the highest-likelihood result rather than selecting a tree by its branch-support values.

12 Operational checklist

  1. Prepare and inspect the aligned input data.
  2. Select the character type and partition scheme.
  3. Choose model selection or state a fixed model.
  4. Set branch-support procedures, a fixed seed, resource limits, and a unique prefix.
  5. Save the exact command, IQ-TREE version, input alignment, and partition file.
  6. Read the .log and .iqtree files and resolve relevant warnings.
  7. Preserve the .treefile, report, log, checkpoint, selected model, and partition scheme.
  8. Root the inferred tree according to the biological study design and document that decision.
  9. Report the software version, model-selection procedure or fixed model, partition model, tree-search settings, support procedures, and replicate counts.
  10. Cite IQ-TREE and each feature-specific method listed in the .iqtree report.
